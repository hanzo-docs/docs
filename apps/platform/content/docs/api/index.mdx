Everything the dashboard does, it does over one public HTTP surface. There is no
second protocol and no second host.

## Base URL

```
https://api.hanzo.ai/v1
```

<Callout type="warn">
`app.platform.hanzo.ai` is the **dashboard**, not an API host. It answers `301`
on every path and redirects to `platform.hanzo.ai`, and `curl` silently
downgrades a `POST` to a `GET` when it follows a `301`. Point programmatic calls
at `api.hanzo.ai`.
</Callout>

## Surfaces

Resources live under `/v1` in groups. They are separate services behind one host,
which is why the path prefixes differ.

| Prefix | Resource | Docs |
|--------|----------|------|
| `/v1/platform/projects/…` | Projects, apps, deploys, env, domains | [Apps](/docs/api/containers) |
| `/v1/machines`, `/v1/gpus`, `/v1/compute/…` | Machines, GPUs, the launch catalog | [Machines](/docs/api/vms) |
| `/v1/clusters`, `/v1/k8s/…` | Clusters, node pools, nodes | [Clusters](/docs/api/clusters) |
| `/v1/iam/…` | Organizations, users, roles, invitations, API keys | [Organizations](/docs/api/organizations) · [Authentication](/docs/api/authentication) |

## Authentication

Every request carries a bearer token, and every request acts as exactly one
organization:

```bash
curl https://api.hanzo.ai/v1/platform/projects \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "X-Org-Id: acme-corp"
```

The org is taken from the **validated** identity. A call with no validated
principal is refused `403` even if it sets `X-Org-Id`, because trusting the
header alone would let an unauthenticated caller act inside someone else's
tenant:

```json
{
  "status": 403,
  "code": "forbidden",
  "error": "X-Org-Id required"
}
```

With a valid bearer, `X-Org-Id` selects which of your orgs the call acts as; a
token bound to exactly one org does not need it. See
[Authentication](/docs/api/authentication) for how to obtain a token.

## Request Format

The HTTP method carries the verb; the path names the resource. Writes take a JSON
body:

```bash
curl -X POST https://api.hanzo.ai/v1/platform/projects/my-app/apps \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "X-Org-Id: acme-corp" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "web",
    "source": "image",
    "image": { "repository": "ghcr.io/myorg/web", "tag": "v1.2.3" },
    "port": 3000
  }'
```

<Callout type="warn">
Routes are keyed by **method as well as path**. `PATCH` is served nowhere;
`PUT` is served on exactly one platform route (replacing an app's env set). An
unregistered verb on a real path answers `404`, not `405` — so a `404` means
"check the method" at least as often as it means "no such resource".
</Callout>

## Response Format

Success returns the resource itself — no envelope:

```json
{
  "id": "app_abc123",
  "slug": "web",
  "name": "web",
  "environment": "production",
  "source": "image",
  "image": { "repository": "ghcr.io/myorg/web", "tag": "v1.2.3" },
  "port": 3000,
  "replicas": 1,
  "status": "running"
}
```

## Error Responses

Errors return the matching HTTP status with a three-field body:

```json
{
  "status": 403,
  "code": "forbidden",
  "error": "X-Org-Id required"
}
```

| Status | Meaning |
|--------|---------|
| `400` | Invalid input |
| `401` | Missing or invalid token |
| `403` | No validated principal, or no organization |
| `404` | No such resource — or that method is not served on this path |
| `409` | Slug or host already claimed |
| `429` | Too many in-flight builds or deploys — retry |
| `500` | Server error |
| `503` | A dependency the write needs (cluster, KMS) is unreachable |

Every response carries `x-request-id`; quote it when reporting a problem.

## Concurrency Limits

Deploys, not reads, are what the platform bounds. Concurrent in-flight image
deploys are capped per organization and concurrent builds are capped in the
cluster; over the cap a deploy is refused `429`, nothing is recorded, and it is
safe to retry. Reads are not rate-limited by the platform.

## Health

```bash
curl https://api.hanzo.ai/v1/platform/health
```

`200` when the control plane can reach the cluster, `503` with the real reason
when it cannot. It is the one route that needs no organization.
