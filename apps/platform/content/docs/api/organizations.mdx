---
title: Organizations API
description: Create, read, update, and delete organizations in Hanzo IAM
---

An organization is the account everything else is named inside — users,
applications, roles, projects, and every app and machine the platform runs for
you. It is an **IAM** resource, so it lives on the IAM surface rather than under
`/v1/platform`.

## Base

```
https://api.hanzo.ai/v1/iam/organizations
```

## Endpoints

The natural key is the `(owner, name)` pair — not a surrogate id — so every read,
update, and delete names both.

| Operation | Request |
|-----------|---------|
| List | `GET /v1/iam/organizations` |
| Get one | `GET /v1/iam/organizations/get` |
| Create | `POST /v1/iam/organizations` |
| Update | `POST /v1/iam/organizations/update` |
| Delete | `POST /v1/iam/organizations/delete` |

<Callout type="warn">
Reads are `GET` and writes are `POST`. There is no `PATCH`, `PUT`, or `DELETE`
verb on this surface — the route table is keyed by method, so sending one gets a
`404`, not a `405`.
</Callout>

## List Organizations

`GET /v1/iam/organizations`

```bash
curl "https://api.hanzo.ai/v1/iam/organizations?owner=acme-corp&limit=20&offset=0" \
  -H "Authorization: Bearer $HANZO_TOKEN"
```

All three query parameters are optional; `owner` scopes the listing, `limit` and
`offset` page it.

**Response:**

```json
{
  "organizations": [
    {
      "owner": "admin",
      "name": "acme-corp",
      "displayName": "Acme Corp",
      "websiteUrl": "https://acme.com",
      "defaultApplication": "acme-console",
      "createdTime": "2026-01-15T10:00:00Z"
    }
  ],
  "count": 1
}
```

## Get Organization

`GET /v1/iam/organizations/get`

```bash
curl "https://api.hanzo.ai/v1/iam/organizations/get?owner=admin&name=acme-corp" \
  -H "Authorization: Bearer $HANZO_TOKEN"
```

`owner` and `name` are both required; either one missing is a `400`, so a
mistyped selector is loud rather than a silent full-table read. An organization
that does not exist is `404`.

**Response:**

```json
{
  "owner": "admin",
  "name": "acme-corp",
  "displayName": "Acme Corp",
  "websiteUrl": "https://acme.com",
  "logo": "https://cdn.acme.com/logo.svg",
  "favicon": "https://cdn.acme.com/favicon.ico",
  "defaultApplication": "acme-console",
  "languages": ["en"],
  "tags": ["production"],
  "mfaRememberInHours": 168,
  "failedSigninLimit": 5,
  "failedSigninFrozenTime": 15,
  "createdTime": "2026-01-15T10:00:00Z"
}
```

Credential material — password salts, obfuscator keys, master and default
passwords, the master verification code — is masked on every read. It is only
ever accepted on the way in.

## Create Organization

`POST /v1/iam/organizations`

```bash
curl -X POST https://api.hanzo.ai/v1/iam/organizations \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "owner": "admin",
    "name": "acme-corp",
    "displayName": "Acme Corp",
    "websiteUrl": "https://acme.com",
    "defaultApplication": "acme-console"
  }'
```

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `owner` | string | Yes | The parent tenant. Half of the natural key |
| `name` | string | Yes | Machine name, unique within `owner` |
| `displayName` | string | No | Human-facing label |
| `websiteUrl` | string | No | Public site |
| `logo`, `logoDark`, `favicon` | string | No | Branding used by the sign-in portal |
| `defaultApplication` | string | No | The app a bare sign-in lands on |
| `languages`, `tags`, `countryCodes` | array | No | Free-form lists |
| `failedSigninLimit` | number | No | Per-org sign-in throttle; `0` inherits the application default |
| `failedSigninFrozenTime` | number | No | Minutes frozen after the limit trips |

The full response is the created organization. A `(owner, name)` already in use
is refused `409` rather than taken over.

## Update Organization

`POST /v1/iam/organizations/update`

The body carries the desired state; its `owner` and `name` select the row.

```bash
curl -X POST https://api.hanzo.ai/v1/iam/organizations/update \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "owner": "admin",
    "name": "acme-corp",
    "displayName": "Acme Corporation",
    "websiteUrl": "https://acme.com"
  }'
```

## Delete Organization

`POST /v1/iam/organizations/delete`

```bash
curl -X POST https://api.hanzo.ai/v1/iam/organizations/delete \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "owner": "admin", "name": "acme-corp" }'
```

**Response:**

```json
{ "affected": true }
```

<Callout type="warn">
Deleting an organization removes the account every user, application, role, and
project is named inside. This cannot be undone.
</Callout>

## Membership

There is no separate team endpoint. Membership and permission are **roles** and
**permissions** on the same IAM surface, and a role carries its member list
directly:

| Resource | List | Create | Get | Update | Delete |
|----------|------|--------|-----|--------|--------|
| Users | `GET /v1/iam/users` | `POST /v1/iam/users` | `GET /v1/iam/users/get` | `POST /v1/iam/users/update` | `POST /v1/iam/users/delete` |
| Roles | `GET /v1/iam/roles` | `POST /v1/iam/roles` | `POST /v1/iam/roles/get` | `POST /v1/iam/roles/update` | `POST /v1/iam/roles/delete` |
| Permissions | `GET /v1/iam/permissions` | `POST /v1/iam/permissions` | `GET /v1/iam/permissions/get` | `POST /v1/iam/permissions/update` | `POST /v1/iam/permissions/delete` |
| Invitations | `GET /v1/iam/invitations` | `POST /v1/iam/invitations` | `POST /v1/iam/invitations/get` | `POST /v1/iam/invitations/update` | `POST /v1/iam/invitations/delete` |

```bash
# Who is in the org
curl "https://api.hanzo.ai/v1/iam/users?owner=acme-corp" \
  -H "Authorization: Bearer $HANZO_TOKEN"

# Put someone in a role — the role owns its member list
curl -X POST https://api.hanzo.ai/v1/iam/roles/update \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "owner": "acme-corp",
    "name": "admins",
    "displayName": "Administrators",
    "users": ["acme-corp/alice", "acme-corp/bob"],
    "isEnabled": true
  }'

# Invite someone in
curl -X POST https://api.hanzo.ai/v1/iam/invitations \
  -H "Authorization: Bearer $HANZO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "owner": "acme-corp",
    "name": "q1-eng",
    "displayName": "Q1 engineering hires",
    "application": "acme-console",
    "quota": 10,
    "state": "Active"
  }'
```

SCIM 2.0 (RFC 7644) is served alongside these for identity providers that
provision users automatically.
