**Research Autopilot turns new evaluation outcomes into bounded follow-up experiments — without timers, polling scripts, or unchecked merges.** When a study finishes reviewing baseline vs. candidate evidence, the durable automation engine wakes an agent against an isolated sandbox to propose and test the next hypothesis.

## Architecture of an autonomous research loop

1. **Trigger**: A study completes review and publishes an `improvement.reviewed` event carrying `review.status` (`improved`, `regressed`, `inconclusive`, `blocked`) plus baseline and candidate hashes.
2. **Deduplicated dispatch**: `/v1/auto/automations` deduplicates by exact evidence digest so retried deliveries never duplicate runs.
3. **Isolated execution**: The agent leases an ephemeral microVM via `POST /v1/sandbox/lease`, runs the benchmark harness, and uploads measured results.
4. **Untrusted data boundary**: Incoming evidence is attached strictly as untrusted data — never executable instructions — and `permissions: "ask"` blocks any unapproved side effect.
5. **Draft output**: Winning candidates open a draft PR with reproduction logs and paired benchmark deltas; humans (or CI gates) own merge and deploy.

## Arm an outcome-triggered research automation

```bash
hanzo auto automations create --data '{
  "name": "Continuous harness research",
  "instructions": "Inspect recorded study evidence. Propose one bounded experiment or tested draft patch. Never fabricate measurements.",
  "event": {"source": "research", "name": "improvement.reviewed"},
  "model": "zen6-coder",
  "permissions": "ask"
```

## Review and trigger manually

- Trigger an on-demand verification pass: `POST https://api.hanzo.ai/v1/auto/automations/{id}/run`
- Inspect past runs newest-first: `GET https://api.hanzo.ai/v1/auto/automations/{id}/runs`
- Approve or reject a held run: `POST https://api.hanzo.ai/v1/auto/automations/{id}/runs/{run}/review`
