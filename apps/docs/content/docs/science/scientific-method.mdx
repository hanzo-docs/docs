**Most AI iteration fails because teams change the prompt, the model, and the eval set in the same commit.** Hanzo enforces five rules of computational experimentation across `/v1/eval`, `/v1/experiment`, and `/v1/benchmark`.

## Five rules of a valid AI experiment

1. **State the falsifiable hypothesis first**: Declare what changes (one independent variable), which metric must rise (`min_gain`), and which guardrails must not regress (`max_regression`).
2. **Freeze the dataset**: Materialize a point-in-time snapshot (`POST /v1/dataset/{name}/materialize`) or pin an `/v1/eval/datasets/{name}` corpus so control and treatment evaluate the exact same items.
3. **Require paired observations**: Compare two arms ONLY over `n_common` — the exact intersection of items both arms completed (`GET /v1/benchmark/compare`). Never compare one arm's easy subset against another arm's full run.
4. **Report uncertainty**: Overlapping confidence intervals or under-powered samples (`n < min_questions`) resolve to `inconclusive`, never `improved`.
5. **Bind authorization to evidence hashes**: Every verdict records the exact hashes of the baseline, candidate, dataset, and policy. Modifying evidence invalidates prior approvals automatically.

## Pre-registration template

Keep this schema in version control beside every prompt, router blend, or harness change:

```json
{
  "hypothesis": "Switching support triage from generative JSON to Kai reduces p95 latency >= 70% at equal or higher macro F1.",
  "baseline": { "model": "enso-pro", "commit": "a1b2c3d" },
  "candidate": { "model": "kai", "capability": "billing-refund-router@v2" },
  "dataset": "refund-policy-golden",
  "min_questions": 50,
  "acceptance": [
    { "metric": "macro_f1", "direction": "higher", "min_gain": 0.0, "max_regression": 0.01 },
    { "metric": "latency_p95_ms", "direction": "lower", "min_gain": 150, "max_regression": 0 }
  ]
}
```
