**An improvement is recursive when each pass strengthens the memory, skill, tool, capability, or harness that produces the next pass — while every promotion remains evidence-gated and reviewable.**

See the full native architecture on [Self-improvement](/docs/self-improvement). This guide focuses on wiring the closed-loop engineering controls.

## Seven stages of a verified improvement cycle

| Stage | Mechanism on Hanzo | Artifact produced |
|---|---|---|
| 1. **Observe** | Production traces (`/v1/eval/traces`), corrections (`/v1/decisions/{decision}/corrections`), Enso feedback (`/v1/ai/feedback`) | Hashed outcome record |
| 2. **Remember** | Scoped memory extraction in `hanzo dev` (`dev memory enable`) | Deduplicated personal or workspace memory |
| 3. **Classify** | Kai `agent.learn@1` chooses `none`, `memory`, `experiment`, or `improvement` | Calibrated recommendation under `kai.toml` mode |
| 4. **Hypothesize** | Improvement study or controlled experiment (`/v1/experiment`) | Falsifiable acceptance spec |
| 5. **Build & Verify** | Isolated `/v1/sandbox` + `hanzo dev` regression harness | Failing-before / passing-after test proof |
| 6. **Review & Publish** | Draft PR or `POST /v1/capabilities/{name}/publish` | Audited release |
| 7. **Re-measure** | `GET /v1/eval/metrics` & `GET /v1/benchmark/history` | Longitudinal delta |

## Wire the three continuous signals

# 2. Emit Enso routing feedback after verified task completion

## Hard safety boundaries

- **No silent scope escalation**: Personal preferences never leak into shared org skills or public product PRs.
- **No self-authorized merges**: `agent.learn@1` cannot expand sandbox permissions, execute untrusted tool output as instructions, or merge its own PRs.
- **Abstention means no-op**: If Kai times out or falls below confidence threshold, no follow-up learning action is spawned.
