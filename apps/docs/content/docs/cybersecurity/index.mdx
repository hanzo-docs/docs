**Never ask an autoregressive LLM to police its own shell commands.** Hanzo treats AI security as a systems engineering problem: deterministic policy floors, calibrated Kai risk gates, hardware-isolated sandboxes, secret and SBOM scanning, KMS secret zeroization, and fine-grained AuthZ.

## Defense-in-depth stack

| Layer | Canonical endpoints & primitives | Security guarantee | Status |
|---|---|---|---|
| **Identity & AuthZ** | Hanzo IAM (`hanzo.id`), `POST /v1/authz/check`, `GET /v1/audit` | Verified principal per request; explicit least-privilege authorization; tamper-evident audit logs | `shipped` |
| **Secrets & KMS** | `GET /v1/kms/secrets`, `POST /v1/kms/secrets`, `POST /v1/security/scans` | Secrets stored in KMS, never in prompts or repos; rule-based secret leak scanning | `shipped` |
| **Command & Prompt Gating** | `POST /v1/decisions` (`agent.command-risk@1`), `POST /v1/risk/score` | Calibrated `allow < ask < deny` verdicts that can only tighten — never loosen — deterministic policy | `shipped` |
| **Execution Isolation** | `POST /v1/sandbox/lease`, `POST /v1/sandbox/{id}/exec` | Untrusted code, exploits, and tool execution confined to ephemeral microVMs | `shipped` |
| **Supply Chain & Trust** | `GET /v1/sbom/{ref}`, `GET /v1/trust/coverage/{framework}`, `GET /v1/compliance/status` | Container digest SBOMs, continuous SOC 2 / compliance control coverage | `shipped` |
| **Zero-Trust Network** | `GET /v1/network/identities`, `GET /v1/network/services` | Identity-authenticated overlay networking with air-gapped self-hosting support | `shipped` |
