**Detection without remediation just builds a bigger backlog.** Autonomous SecOps closes the loop between a confirmed finding and a minimal, regression-tested draft pull request ready for one-click security review.

## Four gates every remediation patch must pass

1. **Failing proof first**: The regression test reproduces the confirmed finding on the base commit (`exit != 0`).
2. **Minimal diff**: `zen6-coder` (via `hanzo dev` or `/v1/agent/{ref}/run`) fixes the root cause without unrelated refactoring.
3. **Full verification**: The new security test passes AND the full existing test suite plus `POST /v1/security/scans` pass with zero new findings.
4. **Human merge authority**: The automation holds the patch at `review` (`POST /v1/auto/automations/{id}/runs/{run}/review`) and opens a draft PR — never pushing straight to production.

## Automate SecOps patch preparation

<Tabs items={['CLI', 'SDK', 'HTTP', 'MCP']}>
<Tab value="CLI">
```bash
hanzo auto automations create --data '{
  "name": "SecOps verified finding patcher",
  "instructions": "Take the validated reproducer test, author the smallest fix in an isolated branch, verify all tests and security scans pass, and open a draft PR.",
  "model": "zen6-coder",
  "permissions": "ask"
}'

# Inspect pending security review runs
hanzo auto automations list
```

## Incident rollback path

If a remediation patch or deployment triggers elevated error rates in `GET /v1/o11y` or `GET /v1/eval/metrics`, roll back immediately via `POST https://api.hanzo.ai/v1/deploy/applications/{name}/rollback` or `POST https://api.hanzo.ai/v1/capabilities/{name}/rollback`.
