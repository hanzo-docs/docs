**Kai fits wherever software makes the same bounded judgment many times:
which queue, which of these, is this safe, how severe.** Each row below is a
decision and the recipe or pattern that runs it end to end against
`api.hanzo.ai`. Where a recipe uses labelled cases from the public benchmark
harness, the last column names the suite, and the recipe prints how often Kai
was right.

## Adapting one

1. **Name the decision and its options.** If the options are open-ended, the
   work belongs to a generative model; Kai picks among options you can list.
2. **Put what decides it in `state`.** The text, and the facts that change
   the answer as separate keys; nothing else
   ([limits](/docs/kai/limits#unrelated-context)).
3. **Run labelled cases before code acts.** Accuracy on a suite covers its
   own labels and wording. A label set, rubric or yes/no question no suite
   measured can do far worse ([limits](/docs/kai/limits)).
4. **Keep the policy in code.** Thresholds, the order of checks and who gets
   the uncertain rest are yours ([patterns](/docs/kai/patterns)).
