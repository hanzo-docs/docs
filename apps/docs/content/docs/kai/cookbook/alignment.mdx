**Two suppliers list the same GPUs under different names; code needs to know
which listings are one product.** The script puts twelve labelled pairs to Kai
with one relation question, one score and a noul per field, and counts what
each got right.

## The idea

Entity alignment is a pair question: do these two records describe one thing,
and if not, where do they differ. The pairs are written the way two feeds
write them. Supplier A spells out the vendor and runs the fields together;
supplier B abbreviates and adds its own details. Six pairs are one product.
Six are a different product that looks close: another form factor, another
memory size, the previous generation, a sibling model.

Each pair goes out as a premise and a hypothesis, which lets one call carry
three kinds of question:

- **relation:** the natural-language-inference choice Kai was trained on,
  entailment, neutral or contradiction. Entailment means the second listing
  follows from the first: the same product.
- **same:** a score from "different products" to "the same product".
- **model, memory, form:** a noul per field, phrased as a statement that the
  field differs, with both sides described.

## The code

```python
PAIRS = [
    ("NVIDIA H100 SXM5 80GB HBM3", "H100 80 GB, SXM form factor", True, (False, False, False)),
    ("NVIDIA H100 SXM5 80GB", "H100 PCIe, 80 GB", False, (False, False, True)),
    ("NVIDIA L40S 48GB", "L40, 48 GB", False, (True, False, False)),
    # ... nine more: supplier A, supplier B, one product, which fields differ
]
FIELDS = {
    "model": ("name different GPU models", "the model names differ, not just their spelling"),
    "memory": ("give different memory sizes", "the memory sizes differ"),
    "form": ("give different form factors", "one is SXM or OAM and the other PCIe, or similar"),
}
QUESTIONS = {
    "relation": Choice(
        instructions="How does `hypothesis` relate to `premise`?",
        criteria={
            "entailment": "the premise implies the hypothesis",
            "neutral": "the premise neither implies nor contradicts the hypothesis",
            "contradiction": "the premise contradicts the hypothesis",
        },
    ),
    "same": Score(
        instructions="Do `premise` and `hypothesis` describe the same product?",
        criteria=["different products", "probably different", "probably the same", "the same product"],
    ),
    **{
        name: Noul(
            instructions=f"`premise` and `hypothesis` {what}.",
            criteria={"true": differ, "false": "they agree, or one of them does not say"},
        )
        for name, (what, differ) in FIELDS.items()
    },
}

for a, b, same, differ in PAIRS:
    state = {"premise": f"Supplier A lists the {a}.", "hypothesis": f"Supplier A lists the {b}."}
    d = kai.decide(state, QUESTIONS)
```

## What the numbers say

- **The relation leans to contradiction and rarely finds a match.** On the six
  different pairs it said contradiction four times, neutral once and entailment
  once, taking the L40S and the L40 for one product. On the six same pairs it
  said entailment twice, neutral three times and contradiction once, for the
  T4. Seven of twelve right.
- **The score does not separate the pairs.** Every score fell between 1.27 and
  2.03, and the highest went to an H200 against an H100: six of twelve right at
  1.5, a coin toss.
- **The field nouls do not find the field.** Model, memory and form differ in
  eight places across the twelve pairs; the nouls reached 0.5 on one of them,
  the L40S against the L40, and on four fields that agree. A field that
  differs by one token, `SXM` against `PCIe` or `80 GB` against `40 GB`, is the
  case they miss.

Do not build an alignment on these answers with the current checkpoint.
[Limits](/docs/kai/limits) tracks what it gets wrong.

## Adapt it

- Compare structured fields in code. Memory is a number, form factor is one of
  a few tokens, a model number is a string: parse them and compare exactly.
- Put the rest to Kai as a relation question, premise and hypothesis, and treat
  its contradiction as a reason to look, not a verdict. Measure it on pairs
  labelled from your own catalogs before it decides anything.
- Keep a person on the pairs code and Kai disagree about.
