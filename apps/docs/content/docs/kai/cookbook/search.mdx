**One page, one question: which line answers it, and does the page answer it
at all.** The script splits the Credits & billing page of these docs into
lines, asks eleven questions of it, eight with a known answering line and
three the page does not answer, and finds the line three ways.

## The idea

A line is a sentence, a table row, a heading or a list item of the page. Three
ways to find the one that answers:

- **a relevance noul per line**, ``Does `line` help answer `query`?``, all
  thirty-five in one call: the RAG relevance question Kai is trained and
  measured on;
- **one choice over the line ids**, each id's description the line's text;
- **keyword search**: BM25 over the lines, in code, with no model.

Whether the page answers at all is a question about the whole page, so it is
asked once, with the page in the state: a noul stated as
`` `document` answers `query`. `` with both sides described. Kai reads up to
1,024 tokens per question, state and question together, and this page fits.

## The code

```python
if not CACHE.exists():
    CACHE.parent.mkdir(exist_ok=True)
    urllib.request.urlretrieve(PAGE, CACHE)
page = lines(CACHE.read_text())
document = "\n".join(f"{key} {line}" for key, line in page.items())
answered = Noul(
    instructions="`document` answers `query`.",
    criteria={"true": "a line of the document gives the answer", "false": "the document does not cover it"},
)
pick = Choice(instructions="Which line of `document` answers `query`?", criteria=page)
per_line = {key: Noul(instructions={"line": line, "question": "Does `line` help answer `query`?"}) for key, line in page.items()}

for query, gold in QUERIES:
    nouls = kai.decide({"query": query}, per_line)
    whole = kai.decide({"query": query, "document": document}, {"line": pick, "answered": answered})
```

The per-line call carries only the query as its state: each noul reads the
query and its own line. The whole script, with the line splitter and the
eleven labelled questions, is
[`search.py`](https://github.com/hanzoai/python-sdk/blob/main/pkg/hanzo-kai/examples/search.py).

## What the numbers say

- **Keyword search found the line best.** BM25 put the answering line first
  for six of the eight answerable questions. Kai's line nouls put it first for
  two and in the top three for five. The single choice over the 35 line ids put
  it first for none: its top line, `L08` five times, held 4 to 7% of the
  probability, against 2.9% for an even spread.
- **The line nouls rank, but their values do not say whether a line answers.**
  The best line scored between 0.280 and 0.592 across all eleven questions,
  and for two of the three questions the page does not answer, some line
  reached 0.45.
- **The page noul nearly separates answered from unanswered.** It gave the
  eight answerable questions 0.341 to 0.515 and the other three 0.298 to
  0.348. Every unanswered question fell below 0.35, and so did one answered
  question. A line drawn there rests on three questions; draw yours on your
  own.

## Adapt it

- Find the line with keyword search, or with the retriever you already run,
  over the page's lines.
- Ask Kai whether the page answers at all, with the page in the state, and set
  the threshold on questions you know the page does and does not answer.
- Keep the page within what Kai reads, 1,024 tokens per question with the
  state. Split a longer page by section and ask the page question of each.
- Do not ask one choice over dozens of line ids.
