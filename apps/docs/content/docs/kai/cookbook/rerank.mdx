---
title: Rerank a shortlist
description: "Reorder a retriever's shortlist with one relevance question per candidate in a single call, and check the new order against labelled queries before trusting it."
---

**A retriever hands over twenty candidates; Kai rates each one against the
question, all in one call.** The script reranks keyword shortlists of the
docs.hanzo.ai pages for twelve questions whose answering page is known, and
scores three orders: the incoming one, Kai's relevance nouls, and Kai's score
questions.

## The idea

Reranking is a relevance judgment per candidate, and a call can carry one
question per candidate. The query is the state; each candidate rides in its own
question's instructions. Kai answers each question as its own sequence, so
twenty candidates cost twenty reads of the query and the candidate, not one
read of everything at once.

The run asks the relevance question two ways:

- **a relevance noul**, ``Does `passage` help answer `query`?``: the question
  Kai's RAG relevance suite trains and measures;
- **a score question** over four levels, from "unrelated" to "answers it".

The incoming order is BM25 over each page's title and description in the docs
index. The labels are ours: for each question, the one page that answers it.

## The code

```python
nouls = {
    f"c{i}": Noul(instructions={"passage": docs[path], "question": "Does `passage` help answer `query`?"})
    for i, path in enumerate(candidates)
}
scores = {
    f"c{i}": Score(instructions={"page": docs[path], "question": "How well does `page` answer `query`?"}, criteria=LEVELS)
    for i, path in enumerate(candidates)
}
by_noul = kai.decide({"query": query}, nouls).nouls
by_score = kai.decide({"query": query}, scores).scores
noul_order = sorted(candidates, key=lambda p: -by_noul[f"c{candidates.index(p)}"].noul)
score_order = sorted(candidates, key=lambda p: -by_score[f"c{candidates.index(p)}"].score)
```

A sort in Python is stable, so candidates Kai rates alike keep their incoming
order. The whole script, with the shortlist and the twelve labelled questions,
is [`rerank.py`](https://github.com/hanzoai/python-sdk/blob/main/pkg/hanzo-kai/examples/rerank.py).

## What the numbers say

- **The incoming order was the best order.** BM25 put the answering page first
  for eight of twelve questions (MRR 0.764). Kai's relevance nouls put it first
  for six (MRR 0.617).
- **The nouls fixed two and broke four.** They moved the LangGraph page from
  third to first and the headless Hanzo Dev page from second to first. They
  moved four pages that were already first down the list: the key rotation
  page to eleventh, the Pinecone page to seventh.
- **Do not rerank with score questions.** They put the answering page last of
  twenty for three questions and never higher than ninth (MRR 0.062): the
  order came out close to reversed.
- **No reranker finds what the retriever missed.** The webhook signing page
  was not in its shortlist, so every order missed it.

On this checkpoint Kai does not improve this retriever. That is a measurement
on twelve questions, not a rule: run your own labelled queries through both
orders before switching.

## Adapt it

- Rerank with the relevance noul, one per candidate, and keep your incoming
  order as the tie-break.
- Keep a labelled set of queries with their answering document, and compare
  first place and MRR for the incoming order against the reranked one whenever
  either side changes.
- Shortlist wide enough that the answer is in it; a reranker only reorders.
