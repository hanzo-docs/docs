title: Pick one skill
description: "Choose at most one skill from the Hanzo skills catalog for an agent's turn with a shortlist and a re-check, and see which shortlist to trust on the current checkpoint."
---

**An agent's turn needs one skill loaded, or none.** The catalog is the 201
skills in the `hanzo` and `core` sections of
[hanzoskills.com](https://hanzoskills.com), built in code from its published
index. The script picks a skill for twelve labelled turns, nine that a skill
fits and three that need none, in two passes: a shortlist of five, then a
re-check of each candidate.

## The idea

Two hundred options is a wide choice. The first pass narrows it to five; the
second asks, candidate by candidate, whether the skill helps with the turn, and
loads the best one only if it clears a threshold. Below the threshold the
answer is no skill, which is the right answer for a turn no skill fits.

The run measures two shortlists for the first pass:

- **Kai's choice**: one choice question over all 201 skills, each described by
  the first 200 characters of its index entry. The top five by probability.
- **BM25**: keyword search in code over each skill's name and description. The
  top five by score.

The re-check is the RAG relevance noul, ``Does `passage` help answer `query`?``,
with the skill's entry as the passage and the turn as the query: the question
Kai's RAG relevance suite trains and measures. One call carries every
candidate from both shortlists.

## The code

```python
skills = catalog()
choose = Choice(instructions="Which skill does this task need?", criteria={name: text[:200] for name, text in skills.items()})

for turn, gold in TURNS:
    ranked = kai.decide({"task": turn}, {"skill": choose}).choices["skill"].probabilities
    by_kai = sorted(ranked, key=ranked.get, reverse=True)
    by_words = lexical(turn, skills)
    both = list(dict.fromkeys(by_kai[:5] + by_words))
    check = {
        f"s{i}": Noul(instructions={"passage": f"{name}: {skills[name]}", "question": "Does `passage` help answer `query`?"})
        for i, name in enumerate(both)
    }
    answers = kai.decide({"query": turn}, check).nouls
    relevance = {name: answers[f"s{i}"].noul for i, name in enumerate(both)}


def pick(shortlist, relevance, threshold):
    """The shortlisted skill the re-check rates highest, or None when none clears the threshold."""
    best = max(shortlist, key=relevance.get)
    return best if relevance[best] >= threshold else None
```

## What the numbers say

- **Kai's choice over the catalog is not a shortlist.** It put a fitting skill
  in its top five for one turn of nine, the ledger turn. Elsewhere the right
  skill ranked between 21st and 114th, and its first pick for the payment
  errors turn was `hanzo-billing`, for the MCP server turn `hanzo-sentry`.
  Re-checking its shortlist got three turns right at 0.5, the three that need
  no skill. Do not ask the current checkpoint to choose among two hundred
  skills.
- **BM25's top five held a fitting skill for eight turns of nine.** The miss is
  the Stripe key turn, whose words do not name secrets.
- **The re-check says no skill when none fits, and too often when one does.**
  Over BM25's shortlist at 0.5 it got six turns of twelve right: all three that
  need no skill, and three that do, `app-port` at 0.77, `slack-gif-creator` at
  0.56 and `hanzo-datastore` at 0.51. For the other six, no candidate reached
  0.5, so they got no skill. It loaded no wrong skill.
- **BM25 alone gets as many right and loads six wrong ones.** Loading its
  first result every time is right for six turns of twelve too, but it loads a
  skill for all three turns that need none and the wrong skill for three
  more. At 0.4 the re-check sits between the two: four skills right, two wrong
  skills loaded, and a skill loaded for two of the three turns that need none.
- **The re-check misses skills its shortlist holds.** For the signature turn
  BM25 had `hanzo-sign` in its five, and the re-check rated `hanzo-contracts`
  higher; for the browser check it rated `hanzo-form` over `webapp-testing`.

On this checkpoint, shortlist in code and use Kai as the veto: the re-check is
worth its call where loading a wrong skill costs more than loading none.

## Adapt it

- Shortlist with keyword search or your own retriever over the catalog, not
  with a choice over the whole catalog.
- Re-check the shortlist with the relevance noul in one call, and set the
  threshold from your own labelled turns: it trades skills loaded for turns
  left without one.
- Load at most one: `pick` returns the best candidate that clears the
  threshold, or none.
