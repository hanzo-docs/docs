## Overview

Hanzo Storage is a **high-performance, S3-compatible object storage server** for AI workloads. It is a fork of SeaweedFS, rebranded and optimized for the Hanzo ecosystem. Written in Go. Live in production on Hanzo K8s clusters.

### Why Hanzo Storage?

- **S3 API Compatible**: Drop-in replacement for Amazon S3; works with any S3 client or SDK
- **Built for AI**: Optimized for large model artifacts, training datasets, and data pipelines
- **Replication**: Configurable per-volume replication across racks and data centres
- **Server-Side Encryption**: SSE-S3 and SSE-KMS for data at rest and in transit
- **Multi-Tenancy**: Isolated namespaces and access boundaries for teams and services
- **Admin UI + shell**: both ship in the repo (`s3/admin`, `s3/shell`) — no separate console service

### Tech Stack

- **Language**: Go (module: `github.com/hanzoai/s3`)
- **Go Version**: 1.26
- **Components**: master (`:9333`), volume (`:8080`), filer (`:8888`), S3 gateway (`:9000`)
- **License**: Apache-2.0

### OSS Base

Fork of [SeaweedFS](https://github.com/seaweedfs/seaweedfs) (Apache-2.0). Repo: `hanzoai/s3` (GitHub name is `s3`, branded as "Hanzo Storage").

It REPLACED an earlier MinIO fork, which is gone. Anything still naming MinIO, `storage-console` or an AGPL licence for this service is describing a stack we no longer run.

## When to use

- Storing model artifacts, checkpoints, and training datasets
- Serving static assets and large files via S3 API
- Providing S3-compatible object storage for Hanzo services
- Replacing Amazon S3 in self-hosted or hybrid deployments
- Bucket lifecycle management (expiration, tiering)

## Hard requirements

1. **Go 1.24+** to build from source
2. **Docker** for container deployment
3. **NVMe/SSD storage** recommended for performance

## One-file quickstart

### Docker (Hanzo build)

```bash
docker build -f Dockerfile.hanzo -t hanzo-storage .
docker run -p 9000:9000 -p 9001:9001 \
  hanzo-storage server /data --console-address :9001
```

### Build from source

```bash
git clone https://github.com/hanzoai/s3.git
cd s3
go build -o hanzo-storage .
./hanzo-storage server /data --console-address :9001
```

### Verify

The filer speaks plain HTTP, so curl is a complete client — nothing to install:

```bash
curl -F file=@model.safetensors http://localhost:8888/buckets/my-bucket/
curl http://localhost:8888/buckets/my-bucket/model.safetensors -o out.bin
curl -H 'Accept: application/json' http://localhost:8888/buckets/my-bucket/
```

Or the AWS CLI against the S3 gateway on `:9000` (`--endpoint-url`, path-style).

### Docker Compose

```yaml
# compose.yml
services:
  storage:
    image: ghcr.io/hanzoai/s3:latest
    ports:
      - "9000:9000"   # S3 gateway
      - "8888:8888"   # filer
    command: server -dir=/data -s3
    environment:
      S3_ROOT_USER: "${S3_ROOT_USER}"
      S3_ROOT_PASSWORD: "${S3_ROOT_PASSWORD}"
    volumes:
      - storage-data:/data

volumes:
  storage-data:
```

```
│  (browser)   │     │  (port 9001)     │
└──────────────┘     └──────────────────┘
```

### SDK Compatibility

Any S3-compatible SDK works. Purpose-built SDKs:

Use the standard AWS SDKs — they are what the rest of the estate uses (43 repos on `aws-sdk-go-v2` alone), so there is one S3 client to know, not two:

| Language | Package |
|----------|---------|
| Go | `github.com/aws/aws-sdk-go-v2/service/s3` |
| JavaScript / TypeScript | `@aws-sdk/client-s3` |
| Python | `boto3` |

Point them at the gateway with a custom endpoint and path-style addressing:
`BaseEndpoint = http://s3.hanzo.svc:9000`, `UsePathStyle = true`.

Set `RequestChecksumCalculation` to `WhenRequired`. Since aws-sdk-go-v2's s3 v1.73 the
default sends CRC32 as an unsigned streaming trailer, which the SDK refuses to send
over plain HTTP — and the in-cluster gateway is plain HTTP.

### Key Features

- **Erasure Coding**: Data protection with configurable redundancy
- **Bucket Policies**: S3-compatible policy documents for access control
- **Object Lifecycle**: Automated expiration, transition, and tiering rules
- **Event Notifications**: Kafka, NATS, MQTT, Elasticsearch, Redis, PostgreSQL, MySQL targets
- **S3 Select**: Query objects with SQL expressions
- **Versioning**: Object versioning with delete markers
- **Replication**: Cross-site bucket replication

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Default credentials | Running with the built-in defaults | Set `S3_ROOT_USER` and `S3_ROOT_PASSWORD` |
| Console not loading | Console address not set | Add `--console-address :9001` |
| Build fails | Go version mismatch | Requires Go 1.24+ |
| Stale MinIO references | Docs or config naming MinIO, `mc`, `storage-console` or AGPL | That fork is gone; the module is `github.com/hanzoai/s3` and the licence is Apache-2.0 |
