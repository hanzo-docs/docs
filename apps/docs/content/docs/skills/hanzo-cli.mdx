## Overview

Hanzo CLI is a **single native binary** written in Rust. Every product of the
cloud is a command group, and each group's subcommands are that product's
operations — generated from the same contract the API, the SDKs and the MCP
tools serve. So the CLI never lags the API: a new endpoint is a new subcommand.

A first word the CLI does not recognize is read as a **task**, and starts an AI
coding session on it.

The full command reference lives at
[CLI Reference](/docs/services/platform/getting-started/cli); this page is the
skill summary.

## When to use

- Signing in and holding several identities at once
- Reaching any cloud product from a terminal or a CI job
- Managing projects, deployments, clusters, logs, keys and secrets
- Running an org's agents
- Starting a coding session on a repo

## Quick reference

| Item | Value |
|------|-------|
| Binary | `hanzo` (Rust, no runtime required) |
| Repo | `github.com/hanzoai/cli` |
| Install | `curl -fsSL hanzo.sh/cli \| sh` |
| npm | `@hanzo/cli` (downloads the same binary) |
| Config | `~/.config/hanzo/config.toml` |
| Credentials | separate `0600` file, written only by `hanzo auth` |
| Auth | Hanzo IAM over OIDC |
| API | `https://api.hanzo.ai`, paths under `/v1/` |

## Installation

```bash
curl -fsSL hanzo.sh/cli | sh
```

The binary is verified against its published sha256 and lands in `~/.local/bin`.
On macOS you can use the tap instead:

```bash
brew install hanzoai/tap/hanzo
```

Releases publish `hanzo-<os>-<arch>.tar.gz` beside a `.sha256` for every
platform, so a CI job can fetch and verify one directly.

```bash
hanzo --version
hanzo --help
```

## Shape

```bash
hanzo GROUP COMMAND [FLAGS]     # a product operation
hanzo "fix the failing test"    # a task — starts a coding session
```

`hanzo --help` lists every group; `hanzo <group> --help` lists its verbs.

Global flags, valid on every subcommand:

| Flag | Description |
|------|-------------|
| `-c`, `--config <FILE>` | Use a different config file for this invocation |
| `-v`, `--verbose` | Increase logging verbosity (repeat for more) |
| `-V`, `--version` | Print the CLI version |
| `--help` | This page, or a subcommand's own help |

## Commands

### Authentication

```bash
hanzo auth login          # Sign in through Hanzo IAM (OIDC)
hanzo auth logout         # Sign out one identity, or --all
hanzo auth show           # The active identity and org
hanzo auth list           # Every identity held, active one marked
hanzo auth use            # Select the active identity
hanzo auth token          # Print the active access token
```

For CI, sign in without an interactive browser and keep the credential off the
command line — `--token -` reads it from stdin, never from argv:

```bash
printf '%s' "$CI_SECRET" | hanzo auth login --provider hanzo --token -
```

### Projects and deploys

```bash
hanzo projects list                    # Every project the org owns
hanzo projects get <slug>              # Settings, live URL, current deployment
hanzo init my-app --template typescript  # Scaffold locally (rust | python | typescript)
hanzo projects deploy <slug>           # Deploy a build
hanzo projects deployments list <slug> # History, newest first
hanzo projects purge <slug>            # Flush the edge cache
```

### Agents

```bash
hanzo agents list             # Every agent defined in the org
hanzo agents run <ref>        # Run one and get the recorded run back
hanzo agents runs <ref>       # Past runs
hanzo agents create           # Define one: model, instructions, tools
```

### Coding sessions

```bash
hanzo code                    # Start a session on our own dev agent
hanzo dev                     # Same, spelled shorter
hanzo desktop                 # Point an agent at the desktop and browser
```

### Everything else

```bash
hanzo clusters list           # Managed and attached BYO clusters
hanzo logs query              # Search the org's logs
hanzo keys get                # API keys the caller holds
hanzo kms secrets list        # Secrets, from KMS
hanzo mcp servers list        # MCP servers registered for the org
hanzo commerce catalog        # Commerce, one verb per operation
hanzo status                  # The whole cloud in one screen
```

## Configuration

The CLI takes no credentials from the environment. Settings are TOML at
`~/.config/hanzo/config.toml` (macOS: `~/Library/Application Support/hanzo/config.toml`),
and credentials are a separate `0600` file that only `hanzo auth` writes.

```bash
hanzo config list                # every setting
hanzo config get network.active  # one dotted key
hanzo config set code.theme auto

hanzo --config ./other.toml ...  # a different file, this invocation only
```

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| `hanzo: command not found` | `~/.local/bin` not on PATH | Add it, or re-run the installer |
| A command starts a coding session | The first word is not a group | Check `hanzo --help` for the real group name |
| Auth fails | Token expired | `hanzo auth login` |
| Wrong org on a command | Another identity is active | `hanzo auth list`, then `hanzo auth use` |
| Config not found | Wrong path | `hanzo config list` prints what it reads |
