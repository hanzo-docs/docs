**After this page you have a working credential and one call that answered.**

Hanzo is one cloud behind one key. Every capability — inference, identity,
storage, money, agents — answers at `https://api.hanzo.ai`, and the CLI, the
SDKs and the MCP tools are all generated from the same description of it. So
there is nothing to wire up per service: get a key once and everything is
reachable.

## 1. Install

<Tabs items={['npm', 'Script', 'Homebrew', 'From source']}>
<Tab value="npm">
```bash
npm i -g hanzo
```

`hanzo` is the CLI and the client in one install.
</Tab>
<Tab value="Script">
```bash
curl -fsSL https://hanzo.sh | sh
```

Installs into `~/.local/bin`. `https://hanzo.sh/cli` installs the CLI alone.
</Tab>
<Tab value="Homebrew">
```bash
brew install hanzoai/tap/hanzo
```
</Tab>
<Tab value="From source">
```bash
git clone https://github.com/hanzoai/cli && cd cli && cargo install --path .
```
</Tab>
</Tabs>

```bash
hanzo version
```

## 2. Log in

```bash
hanzo auth login
```

That opens a browser against [hanzo.id](https://hanzo.id), Hanzo's identity
provider, and stores the resulting credential locally. `hanzo auth show` prints
who you are; `hanzo auth list` shows every identity on this machine and
`hanzo auth use` switches between them.

<Callout type="warn">
There is no `hanzo login`. A bare word the CLI does not recognise starts a
coding session about that word, so `hanzo login` would open an agent and ask it
about logging in.
</Callout>

For a server, mint a key instead of logging a person in: **console.hanzo.ai →
API keys**. A secret key resolves to *you*, so it belongs on a server and never
in a browser — [Authentication](/docs/api-keys) is the whole rule.

```bash
export HANZO_API_KEY=sk-...
```

## 3. Your first call

The catalogue of models the gateway currently serves. It is a read, it needs
nothing but the key, and it is the same operation on all four surfaces.

<Tabs items={['CLI', 'SDK', 'HTTP', 'MCP']}>
<Tab value="CLI">
```bash
hanzo models list
```
</Tab>
<Tab value="SDK">
<Tabs items={['TypeScript', 'Python', 'Go', 'Rust', 'Swift', 'Kotlin']}>
<Tab value="TypeScript">
```bash
npm i hanzo
```

```ts
import { Hanzo } from 'hanzo'

const hanzo = new Hanzo({ apiKey: process.env.HANZO_API_KEY })
const models = await hanzo.models.list()
```
</Tab>
<Tab value="Python">
```bash
pip install hanzo
```

```python
from hanzo import Hanzo

hanzo = Hanzo(api_key=os.environ["HANZO_API_KEY"])
models = hanzo.models.list()
```
</Tab>
<Tab value="Go">
```bash
go get github.com/hanzoai/go-sdk
```

```go
client := hanzo.NewClient(hanzo.WithAPIKey(os.Getenv("HANZO_API_KEY")))
models, err := client.Models.List(ctx)
```
</Tab>
<Tab value="Rust">
```bash
cargo add hanzo
```

```rust
let hanzo = hanzo::Client::from_env()?;
let models = hanzo.models().list().await?;
```
</Tab>
<Tab value="Swift">
```swift
// Package.swift: .package(url: "https://github.com/hanzoai/swift-sdk", from: "1.0.0")
let hanzo = Hanzo(apiKey: ProcessInfo.processInfo.environment["HANZO_API_KEY"]!)
let models = try await hanzo.models.list()
```
</Tab>
<Tab value="Kotlin">
```kotlin
// build.gradle.kts: implementation("ai.hanzo:sdk:latest.release")
val hanzo = Hanzo(apiKey = System.getenv("HANZO_API_KEY"))
val models = hanzo.models.list()
```
</Tab>
</Tabs>

Every one of these is generated from the same description of the API, so the
method names line up across languages. [C++](/docs/sdks/cpp) is the one still
landing.
</Tab>
<Tab value="HTTP">
```bash
curl https://api.hanzo.ai/v1/models \
  -H "Authorization: Bearer $HANZO_API_KEY"
```
</Tab>
<Tab value="MCP">
```bash
curl -X POST https://api.hanzo.ai/v1/mcp \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

One door, one tool per capability. `tools/call` names the capability and the
operation; `describe` explains any operation's input.
</Tab>
</Tabs>

Those are one API seen from four places, and the tabs above are the whole
difference. Pick the one you will write in:

- **[CLI](/docs/cli)** — every capability as a command group, one page each.
- **[SDKs](/docs/sdks)** — Python, TypeScript, Go, Rust, C++, Swift and Kotlin,
  generated from the same description the CLI and the tools are.
- **[MCP](/docs/mcp)** — one door an agent connects to; [the tools](/docs/mcp-tools)
  are listed one per capability.

HTTP needs no page: it is `https://api.hanzo.ai` and the key you just exported.

## 4. Something that costs money

```bash
hanzo chat completions --model zen-1 --messages '[{"role":"user","content":"hello"}]'
```

Then read what it drew down:

```bash
hanzo billing balance
hanzo usage summary
```

[Credits & billing](/docs/credits) explains what a credit is and what happens at
zero; [Pricing](/docs/pricing) is the rate for every model and tool.

## 5. Run the whole cloud yourself

The same binary that serves `api.hanzo.ai` runs on your machine:

```bash
hanzo up cloud
```

Bare `hanzo up` is the same thing — `cloud` is the default. Name one service to
run it alone: `hanzo up iam`, `hanzo up kms`, `hanzo up gateway`, `hanzo up
storage`, `hanzo up pubsub`. See [Run your own](/docs/network) for what that
means and what it needs.
