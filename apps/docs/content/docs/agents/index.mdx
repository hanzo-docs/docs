## You are a builder agent

### 1. Headless: sign in with a wallet

A wallet is the whole credential: no person, browser, inbox or card. A
first-seen wallet gets its own Hanzo account and organization, with a small free
allowance to try it, and its private key never leaves your process. One file
does all of it:

```ts title="headless.mts"
// No human required: sign in with a wallet, get a key, call the API, top up in USDC.
// A first-seen wallet gets its own Hanzo account and organization, on the Free plan.
// npm i viem   ·   node headless.mts   (Node 22.18+; set HANZO_WALLET_KEY to use your own wallet)
import { createHash, randomBytes } from 'node:crypto'
import { generatePrivateKey, privateKeyToAccount } from 'viem/accounts'

const ID = 'https://hanzo.id'
const API = 'https://api.hanzo.ai'
const CLIENT = 'hanzo-ai'
const REDIRECT = 'http://localhost:3000/callback'

// Your agent's own wallet, or a fresh one. The key never leaves this process.
const account = privateKeyToAccount((process.env.HANZO_WALLET_KEY as `0x${string}`) ?? generatePrivateKey())

const json = async (r: Response) => {
  const body = await r.json()
  if (!r.ok || body?.status === 'error') throw new Error(`${r.url} ${r.status} ${JSON.stringify(body)}`)
  return body
}

// 1. A one-time challenge for this wallet.
const { data: c } = await json(await fetch(`${ID}/v1/iam/web3/nonce?chain=evm&address=${account.address}`))

// 2. The CAIP-122 message the challenge describes, signed with EIP-191 personal_sign.
const message = [
  `${c.domain} wants you to sign in with your Ethereum account:`,
  account.address,
  '',
  ...(c.statement ? [c.statement, ''] : []),
  `URI: ${c.uri}`,
  `Version: ${c.version}`,
  `Nonce: ${c.nonce}`,
  `Issued At: ${c.issuedAt}`,
  ...(c.expirationTime ? [`Expiration Time: ${c.expirationTime}`] : []),
].join('\n')
const signature = await account.signMessage({ message })

// 3. Verify: a first-seen wallet gets an account and an organization of its own.
const verifier = randomBytes(32).toString('base64url')
const challenge = createHash('sha256').update(verifier).digest('base64url')
const { data: code } = await json(
  await fetch(`${ID}/v1/iam/web3/verify`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      clientId: CLIENT, chain: 'evm', scheme: 'secp256k1-eip191', address: account.address, message, signature,
      type: 'code', redirectUri: REDIRECT, scope: 'openid profile email', codeChallenge: challenge, codeChallengeMethod: 'S256',
    }),
  }),
)

// 4. The authorization code for a token.
const token = await json(
  await fetch(`${ID}/v1/iam/oauth/token`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams({ grant_type: 'authorization_code', client_id: CLIENT, code, code_verifier: verifier, redirect_uri: REDIRECT }),
  }),
)
const bearer = { Authorization: `Bearer ${token.access_token}`, 'Content-Type': 'application/json' }

// 5. A key that outlives the token. Shown once: keep it in your secret store.
const minted = await json(await fetch(`${API}/v1/account/keys`, { method: 'POST', headers: bearer, body: JSON.stringify({ name: 'agent', type: 'secret' }) }))
const key = { Authorization: `Bearer ${minted.key}`, 'Content-Type': 'application/json' }

// 6. A first call, free.
const chat = await fetch(`${API}/v1/chat/completions`, {
  method: 'POST', headers: key,
  body: JSON.stringify({ model: 'zen-free', messages: [{ role: 'user', content: 'Reply with the single word: ready' }] }),
})
console.log('chat', chat.status, chat.headers.get('x-hanzo-served'), 'free left today:', chat.headers.get('x-ratelimit-remaining'))
console.log((await chat.json()).choices?.[0]?.message?.content)

// 7. Top up in USDC: ask for a deposit address, then send to exactly that address.
console.log(await json(await fetch(`${API}/v1/billing/crypto/options`, { headers: key })))
console.log(await json(await fetch(`${API}/v1/billing/crypto/deposit`, { method: 'POST', headers: key, body: JSON.stringify({ chain: 'base', token: 'usdc', amountCents: 500 }) })))
console.log('HANZO_API_KEY=' + minted.key.slice(0, 12) + '…  (store the whole key; it is shown once)')
```

```bash
npm i viem && node headless.mts
```

Node 22.18 or later runs the TypeScript as is. Set `HANZO_WALLET_KEY` to sign
with your agent's own wallet; without it the script makes a fresh one. A real run:

```text
chat 200 zen-free free left today: …
ready
{ chains: [ 'base', 'ethereum', 'solana' ], tokens: [ 'usdc', 'usdt' ] }
{ id: 'GRncZpMYqBuV', status: 'pending', chain: 'base', token: 'usdc', depositAddress: '0x…', expiresAt: '2026-10-27T20:33:54Z' }
HANZO_API_KEY=sk-live-1ea7…  (store the whole key; it is shown once)
```

Each request with its answer, then limits, a 429, the deposit and the
balance: [Headless, step by step](/docs/agents/headless). The deposit address is
held in MPC custody per payer; the balance is credited when the chain confirms.

The script signs with EVM. Wallets on Solana, Bitcoin, TON, XRP, Polkadot and
Cardano sign in too (`chain` `solana`, `bitcoin`, `ton`, `xrp`, `polkadot`,
`cardano`). On Solana the message says `Solana account`, `scheme` is `ed25519`,
and the signature goes as base64 or `0x` hex, not base58:
[step 2](/docs/agents/headless#2-sign-it).

### 2. Or get a credential through a person or an inbox

**With your person nearby.** This works on a machine with no browser.

```bash
curl -fsSL https://hanzo.sh | sh
hanzo auth login
export HANZO_API_KEY="$(hanzo auth token)"
```

With no display, `hanzo auth login` prints a link and an 8-character code, and
your person approves it on any device. `hanzo auth token` is a one-hour access
token. For a key that does not expire:

```bash
hanzo account keys create --name agent --type secret
```

The same device flow without the CLI is one request and a poll. The answer
carries `user_code` and `verification_uri_complete` for your person,
`device_code` for you, `expires_in` 900 and `interval` 5:

```bash
curl -X POST 'https://hanzo.id/v1/iam/oauth/device?client_id=hanzo-cli&scope=openid%20profile%20email&response_type=device_code'

# every 5 seconds until your person approves
curl -X POST https://hanzo.id/v1/iam/oauth/token \
  -d grant_type=urn:ietf:params:oauth:grant-type:device_code \
  -d client_id=hanzo-cli -d device_code=<device_code>
```

**On your own, with an inbox.** Four requests. They create a passwordless,
email-verified account and a personal organization it administers. Creating it
accepts the [Terms](https://hanzo.ai/legal/terms) and the [Acceptable Use
Policy](https://hanzo.ai/legal/acceptable-use).

a. Ask for a code. It is 6 digits, lives 10 minutes, takes 5 tries and can be
resent after 30 seconds.

```bash
curl -X POST https://hanzo.id/v1/iam/verification-codes \
  -F type=email -F dest=you@example.com -F applicationId=admin/hanzo-ai
```

b. Sign in with it. `codeChallenge` is the S256 hash of a verifier you keep for
step c. Send `"create": false` first to learn whether the address may sign up;
that does not spend the code.

```bash
curl -X POST https://hanzo.id/v1/iam/login \
  -H "Content-Type: application/json" \
  -d '{"type":"code","organization":"hanzo","clientId":"hanzo-ai","username":"you@example.com","code":"123456","create":true,"terms":"terms-2026-09-30","aup":"aup-2026-09-30","redirectUri":"http://localhost:3000/callback","responseType":"code","scope":"openid profile email","codeChallenge":"<S256 of verifier>","codeChallengeMethod":"S256"}'
```

It answers `{"data":"<authorization code>"}`.

c. Exchange the code for an access token.

```bash
curl -X POST https://hanzo.id/v1/iam/oauth/token \
  -d grant_type=authorization_code -d client_id=hanzo-ai \
  -d code=<authorization code> -d code_verifier=<verifier> \
  -d redirect_uri=http://localhost:3000/callback
```

d. Mint a key with it.

```bash
curl -X POST https://api.hanzo.ai/v1/account/keys \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"agent","type":"secret"}'
```

The answer's `key` is an `sk-` secret, shown once. Keep it as `HANZO_API_KEY`.
Each person gets 30 key writes a minute, and an org holds up to 1,000 live keys.
Key types and revocation: [Authentication](/docs/api-keys).

### 3. Use the free allowance

Free costs nothing and needs no card, to sign up or to mint a key.

- A wallet account: a small free allowance to try it. Read it live:
  `GET /v1/allowance` and `GET /v1/billing/tier`.
- A person on the Free plan: 50 requests a day on the free models (`zen-free`,
  `enso-free`, `zen5`, `zen5-flash`, `zen5-mini`, `zen5-pro`, `zen5-coder`) and

Read the plans with no key: `curl https://api.hanzo.ai/v1/billing/plans`. How to

### 5. Add the MCP server

One local server over stdio works in all four clients. It carries files, shell,
git, search, browser and the Kai tools (`kai_decide`, `kai_choice`,
`kai_score`, `kai_tool_select`, `kai_command_guard`, `kai_injection_screen` and
more).

Claude Code:

```bash
claude mcp add hanzo --env HANZO_API_KEY=$HANZO_API_KEY -- npx -y --package=@hanzo/mcp@latest hanzo-mcp serve
```

Codex, in `~/.codex/config.toml`:

```toml
[mcp_servers.hanzo]
command = "npx"
args = ["-y", "--package=@hanzo/mcp@latest", "hanzo-mcp", "serve"]

[mcp_servers.hanzo.env]
HANZO_API_KEY = "sk-..."
```

Cursor, in `.cursor/mcp.json` or `~/.cursor/mcp.json`:

```json
{ "mcpServers": { "hanzo": { "command": "npx", "args": ["-y", "--package=@hanzo/mcp@latest", "hanzo-mcp", "serve"], "env": { "HANZO_API_KEY": "sk-..." } } } }
```

Zed, in `settings.json`:

```json
"context_servers": { "hanzo": { "command": "npx", "args": ["-y", "--package=@hanzo/mcp@latest", "hanzo-mcp", "serve"], "env": { "HANZO_API_KEY": "sk-..." } } }
```

Name the package and the binary separately: `npx -y @hanzo/mcp serve` reads
`serve` as a second package.

The hosted endpoint, `POST https://api.hanzo.ai/v1/mcp`, speaks MCP protocol
2026-07-28 only. Use it from a client that speaks 2026-07-28; from any other,
use the local server. More: [MCP](/docs/mcp).

### 6. Evaluate Kai yourself

Kai is the decision model: typed questions about a state, answered with
calibrated probabilities.

```bash
curl https://api.hanzo.ai/v1/decisions \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"kai","state":{"ticket":"The export button throws a 500 error since this morning."},"questions":{"team":{"type":"choice","instructions":"Which team should handle this ticket?","criteria":{"billing":"charges, invoices, refunds","tech":"bugs, errors, outages","other":"anything else"}}}}'
```

```json
{"id":"dec_e0bb4a5c…","model":"kai","answers":{"team":{"type":"choice","choice":"tech","confidence":0.951,"probabilities":{"billing":0.004,"tech":0.967,"other":0.028}}},"usage":{"input_tokens":41,"output_tokens":0},"routing":{"backend":"kai","checkpoint":"kai-1.9","device":"cpu","trained":1024,"reach":32768,"extrapolated":false},"latency_ms":121.2}
```

Kai costs \$0.021 per million input tokens, and output is free. Run the frozen

### 7. Respect the rate limits

Every answer carries `X-RateLimit-Limit`, `X-RateLimit-Remaining` and
`X-RateLimit-Reset` (unix seconds), for the tightest limit in play.

| Where | Limit |
| --- | --- |
| Before auth, per IP | 100 requests a second |
| `/v1/decisions` with a credential, per org | 60,000 requests a minute |
| Free chat, a person on the Free plan | 50 requests a day |
| Free chat, a wallet account | a small free allowance: `GET /v1/allowance` |

A refusal is 429. Wait for `X-RateLimit-Reset` or `Retry-After`. The free cap
names itself:

```json
{"error":{"type":"rate_limit_error","code":"free_plan_cap","resets_at":"…","topup_url":"https://hanzo.ai/…","actions":[{"kind":"wait"},{"kind":"topup"}]}}
```

To raise it, top up: `POST /v1/billing/crypto/deposit`, then calls past the
allowance draw on the balance. [Every step](/docs/agents/headless#7-a-429-means-the-free-allowance-is-used).

**Bound every key.** These fields go on `POST /v1/account/keys`, or as the same
flags on `hanzo account keys create`.

| Field | What it does | Past it |
| --- | --- | --- |
| `budget` | `{"month": <cents>, "total": <cents>}` | 402 |
| `rate` | requests per minute | 429 |
| `limit` | narrows the key, never widens it: `model:`, `project:` or `product:` entries | — |
| `expires` | an RFC 3339 time | — |

```bash
curl -X POST https://api.hanzo.ai/v1/account/keys \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"agent","type":"secret","budget":{"month":2000},"limit":["model:zen-free"]}'
```

**Cap a session.** One agent run gets its own ceiling, in micro-USD:

```bash
curl -X POST https://api.hanzo.ai/v1/agent/sessions/<id>/budget \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"budget_micro_usd": 5000000}'
```

A new cap must exceed what the session already spent. Raising it resumes a
paused session; `null` removes the cap for good. `GET /v1/agent/sessions` lists
the sessions. More: [Budgets](/docs/concepts/budgets).

## Questions

**Does an agent need a person to sign up?** No. A wallet signs in, gets its own
account and organization, and mints a key (step 1).

**What is free?** A wallet account gets a small free allowance to try it
(`GET /v1/allowance`). A person on the Free plan gets 50 requests a day on the
free models and 50 Kai decisions a day. Signing up and minting a key need no
card.

**What does it cost after that?** Usage is per token: `zen6` is \$0.60 in and
\$2.40 out per million tokens, and Kai is \$0.021 per million input tokens with
free output. Plans start at \$20 a month. [Pricing](/docs/pricing) has every rate.

**How do I stop an agent's spend?** Give its key a `budget` (402 past it) and a
`rate` (429 past it), cap its session, or revoke the key. A free account has no
card on file to charge.

**Can an agent pay without a browser?** Yes: a USDC or USDT deposit over the
API. Card checkout needs a browser.

**Does it take x402?** x402 settles priced marketplace tools from the prepaid
balance. Chat, decisions and the rest of the API draw on the balance and the
plan.

**What happens when the free allowance runs out?** A 429 with code
`free_plan_cap`, `resets_at` and `topup_url`. Wait for the reset, or top up in
USDC or USDT over the API and go on.

**Why does my client refuse the hosted MCP endpoint?** It speaks protocol
2026-07-28 only. Run the local server above instead.
