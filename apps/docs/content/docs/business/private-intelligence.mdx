**Prompt wrappers have zero defensibility — anyone can copy a system prompt in ten minutes.** Real AI moats come from verified feedback loops over proprietary operational data: calibrated Kai capabilities trained on your domain outcomes, org-specific Enso routing policies, and fine-tuned Zen weights.

## The three-layer private intelligence moat

1. **Decision moat (Kai Capabilities)**: Capture production states and domain expert corrections (`POST /v1/decisions/{decision}/corrections`) and train specialized CPU capabilities (`POST /v1/capabilities/{name}/train`). Your internal policies compile into calibrated sub-50 ms decision heads that never leak into public weights.
2. **Economic moat (Enso Routing)**: Record objective task outcomes (`POST /v1/ai/feedback`) and define custom router blends (`POST /v1/benchmark/presets`) that deliver higher gross margin per customer request than competitors hardcoding frontier models.
3. **Synthesis moat (Fine-Tuned Zen)**: Train LoRA/QLoRA or RL adapters (`POST /v1/train/jobs`, `/v1/train/clients`) on open-weight Apache-2.0 `zen6` so you own the adapter weights outright and can run them hosted or on your own GPUs.

```ts
import { Configuration, CapabilitiesApi, BenchmarkApi, TrainApi } from 'hanzoai';

const cfg = new Configuration({ accessToken: process.env.HANZO_API_KEY });
const [caps, presets, jobs] = await Promise.all([
  new CapabilitiesApi(cfg).capabilitiesList(),
  new BenchmarkApi(cfg).getBenchmarkPresets(),

```

## Licensing & self-hosted delivery

For enterprise customers requiring on-premise deployment of your packaged software or models, issue cryptographically signed offline licenses via `POST https://api.hanzo.ai/v1/licensing/issue` and verify them locally against `GET https://api.hanzo.ai/v1/licensing/pubkey`.
