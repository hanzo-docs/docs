`hanzo dev` runs a coding agent against the repository you are standing in.
Five agents are supported, and naming one gets you that agent or a clear
failure — they are separate products, never aliases of each other.

```bash
curl -fsSL hanzo.sh | sh      # install the CLI (macOS, Linux, WSL)
hanzo                         # sign in, pick your coding agent, launch it
```

On its first run `hanzo` signs you in through your browser, links the machine to
Hanzo Tabs, asks once which coding agent is your favourite, adds Hanzo's tools to
it and launches it accelerated. After that `hanzo` alone launches your favourite,
`hanzo dev --claude`, `--codex`, `--cursor` or `--agy` switches it and saves the
choice, and `hanzo -- -c` continues the last conversation. Or paste this into the
agent and let it install the CLI:

```text
Set up Hanzo on this machine: follow https://hanzo.sh/setup.md
```

Which plan accelerates your own coding tools is in the [quickstart](/docs/quickstart#what-your-plan-unlocks).

```bash
hanzo dev                       # Hanzo Dev, the default
hanzo dev --claude              # Claude Code
hanzo dev --codex               # Codex
hanzo dev --cursor              # Cursor's agent CLI
hanzo dev --agy                 # Antigravity
```

Each tool runs on your own logged-in account, directly. When local Zen and Kai
run on the machine, routine turns go to them. Hanzo's cloud models answer only
when your own account hits its usage limit — on your Hanzo plan, until the limit
resets — or when you pass `--cloud`. Each tool has a [guide](/docs/guides/coding),
with how to read what a session used.

Give it a task as **one** argument, quoted:

```bash
hanzo dev "fix the failing test in api/users"
hanzo dev --claude "port this module to the new store"
```

## Naming the agent

Every spelling below resolves in one place, so they cannot drift apart:

| | Flag | Positional | Explicit |
| --- | --- | --- | --- |
| Hanzo Dev | `hanzo dev` | — | `hanzo dev --backend dev` |
| Claude Code | `hanzo dev --claude` | `hanzo dev claude` | `hanzo dev --backend claude` |
| Codex | `hanzo dev --codex` | `hanzo dev codex` | `hanzo dev --backend codex` |
| Cursor | `hanzo dev --cursor` | `hanzo dev cursor` | `hanzo dev --backend cursor` |
| Antigravity | `hanzo dev --agy` | `hanzo dev agy` | `hanzo dev --backend agy` |

The flag is the spelling these docs use. `claude-code` and
`cc` are accepted spellings of `claude`, `agent` and `cursor-agent` of `cursor`,
and `antigravity` of `agy`.

Naming it twice is refused rather than resolved — `hanzo dev --claude --codex`
tells you to name it once.

## Approvals

The agent auto-approves its own steps by default. Two ways out, in increasing
order of how much they give up:

```bash
hanzo dev --ask             # the backend asks before each step
hanzo dev --no-sandbox      # bypass approvals AND drop the sandbox
```

`--safe` is a synonym for `--ask`, and either wins over `autoApprove` in
`~/.hanzo/settings.json`.

## Model calls and the session

```bash
hanzo dev --claude --cloud      # Hanzo's cloud models, on your Hanzo plan
hanzo dev --claude --no-link    # the session is not shown in the cloud
```

Without `--cloud`, Claude Code and Codex use your own account, and Hanzo's cloud
models take over only at that account's usage limit. Every run you are signed in
for is shown in the cloud as a session unless you pass `--no-link`.

When a session ends, `hanzo dev` prints its duration, tokens, cached share, cost
at the listed price and a link to the session. `hanzo console` (press `6`) and
`hanzo usage summary` show the same usage across sessions. See
[Coding tools](/docs/guides/coding) for what each figure means.

## `hanzo code` is the code index

`hanzo code context`, `hanzo code file` and `hanzo code index` are not the
launcher: they are the [code intelligence API](/docs/openapi/code) — search and
symbols across your indexed repositories, for you and for agents. They take no
backend and run no agent.

On `hanzo dev` the rule is the first argument: a word that names a backend
selects one, and anything else is a task.
