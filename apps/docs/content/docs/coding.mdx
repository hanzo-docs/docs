`hanzo` runs a coding agent against the repository you are standing in. Hanzo Dev is the default. Every other agent is a flag, and naming one gets you that agent or a clear failure.

```bash
curl -fsSL hanzo.sh | sh       # install
hanzo                          # sign in, pick your agent, start it
hanzo --claude                 # Claude Code
hanzo --codex                  # Codex
hanzo --gemini                 # Gemini CLI; also --qwen, --opencode, --kilo, --crush, --goose, --aider,
                               # --hermes, --pi, --copilot, --amp, --grok, --cline, --continue, --kimi,
                               # --omp, --letta, --kode, --cursor, --agy
hanzo --claude "fix the failing test in api/users"   # one quoted task runs headless
```

`hanzo dev` is the same launcher, and `hanzo code` is `hanzo dev`. Each agent keeps its own login and plan. The Hanzo toolset is attached for the run, so the agent can hand work to Enso, Kai and Hanzo's search tools. `--cloud` moves the agent's own model calls onto Hanzo too. When the session ends, the summary names every hand-off and the model that took it.

[Coding tools](/docs/guides/coding) has the full table of agents, sign-up and plans, what each flag does, and how to read the summary.

## The other `hanzo code`

`hanzo code search`, `hanzo code context`, `hanzo code file` and `hanzo code index` are a different thing that shares the word: they are the [code intelligence API](/docs/openapi/code), search and symbols across your indexed repositories, for you and for agents. They take no agent and run none. The rule is the word after `code`: an operation of the code index runs it, and anything else starts a session.
