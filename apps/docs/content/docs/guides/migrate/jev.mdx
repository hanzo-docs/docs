Jev is TypeSafe's decision model. Kai is Hanzo's, served at
[`POST https://api.hanzo.ai/v1/decisions`](/docs/decisions). Both take a state
and named `choice`, `noul` and `score` questions, and both answer with the same
typed shapes, so a Jev integration moves by changing where it points, not what
it asks.

| You call Jev through | Change |
|---|---|
| TypeSafe's SDK, `typesafe-sdk` or `@typesafe-ai/sdk` | [two settings](#keep-typesafes-sdk), or [switch SDK](#switch-to-hanzo-kai-or-hanzokai) |
| OpenRouter's Decisions API | [base URL, key and `model`](#from-openrouter) |
| HTTP to `api.typesafe.ai/v1/systemone` | the URL to `https://api.hanzo.ai/v1/decisions`, the key, and `model` to `kai` |

Every call needs a Hanzo secret key (`sk-`, see [API keys](/docs/api-keys)) on
an org whose plan covers paid models; without one the answer is `402` with
`"code": "plan_required"`.

## Keep TypeSafe's SDK

TypeSafe's SDKs post to their base URL plus `/v1/systemone`, and Hanzo serves
that path for Kai with Jev's request and response shapes. Two settings move a
program, with a Hanzo key in place of the TypeSafe one:

```bash
export TYPESAFE_BASE_URL=https://api.hanzo.ai
export TYPESAFE_DEFAULT_MODEL=kai
export TYPESAFE_API_KEY="$HANZO_API_KEY"
```

Nothing else changes. This program is TypeSafe's Python SDK, unedited,
answered by Kai:

```python
from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

with TypeSafeClient() as client:
    result = client.system_one(
        state={"ticket": "I was charged twice for my March invoice. Please refund the duplicate today."},
        questions={
            "team": Choice(
                instructions="Which team should handle `ticket`?",
                criteria={"billing": "charges, invoices and refunds", "technical": "bugs and outages", "account": "logins and profiles"},
            ),
            "refund": Noul(
                instructions="`ticket` asks for money back.",
                criteria={"true": "a refund or reversal is requested", "false": "no money is requested back"},
            ),
            "urgency": Score(instructions="How urgent is `ticket`?", criteria=["later", "this week", "today", "now"]),
        },
    )

print(result.model, result.choices["team"].choice, result.nouls["refund"].noul, result.scores["urgency"].score, result.usage.input_tokens)
```

The same program through `@typesafe-ai/sdk` prints the same answers. Checked
with `typesafe-sdk` 0.7.2 and `@typesafe-ai/sdk` 0.6.0. `model` in the answer is
Kai's versioned id, `kai-` and the first 12 hex digits of its weights' SHA-256,
and a request may name that id to pin the checkpoint. `kai` is the only model
this path serves: a Jev id such as `jev-latest` answers `400` with
`{"detail": "Unknown model: jev-latest"}`, so a program that still names Jev
fails loudly instead of being answered by another model.
`client.models.list()` returns an empty list without error; Kai's catalogue
rows are at `GET /v1/models`.

## Switch to hanzo-kai or @hanzo/kai

Hanzo's SDKs have the same call shapes under Hanzo's names, so the port is the
import line and the method name:

<Tabs items={['Python', 'TypeScript']}>
<Tab value="Python">
```diff
- from typesafe_sdk import Choice, Noul, Score, TypeSafeClient
+ from hanzo_kai import Choice, Noul, Score, Kai

- with TypeSafeClient() as client:
-     result = client.system_one(state=state, questions=questions)
+ with Kai() as client:
+     result = client.decide(state=state, questions=questions)
```
</Tab>
<Tab value="TypeScript">
```diff
- import { choice, noul, score, TypeSafeClient } from "@typesafe-ai/sdk";
+ import { choice, noul, score, Kai } from "@hanzo/kai";

- const client = new TypeSafeClient();
- const { answers } = await client.systemOne({ state, questions });
+ const client = new Kai();
+ const { answers } = await client.decide({ state, questions });
```
</Tab>
</Tabs>

| TypeSafe | Hanzo |
|---|---|
| `pip install typesafe-sdk` / `npm i @typesafe-ai/sdk` | `pip install hanzo-kai` / `npm i @hanzo/kai` |
| `TypeSafeClient`, `AsyncTypeSafeClient` | `Kai`, `AsyncKai` (Python) |
| `system_one(...)` / `systemOne(...)` | `decide(...)` |
| `SystemOneResponse` / `SystemOneResult<Q>` | `Decision` / `Decision<Q>` |
| `Choice`, `Noul`, `Score`, `choice()`, `noul()`, `score()` | the same |
| answers: `.choices`, `.nouls`, `.scores`, `.answers`, `.usage` | the same |
| `client.models.list()` | the same, listing the models that answer decisions |
| `RetryPolicy`, `extra_headers`, `extra_body`, `response_model`, `withResponse()` | the same |
| `TypeSafeError` and the `APIError` family | `KaiError` and the same family, plus `PaymentRequiredError` for `402` |
| `TYPESAFE_API_KEY`, `TYPESAFE_BASE_URL`, `TYPESAFE_DEFAULT_MODEL`, `TYPESAFE_LOG_LEVEL` | `HANZO_API_KEY`, `HANZO_BASE_URL`, `KAI_MODEL`, `KAI_LOG_LEVEL` |

To keep TypeSafe's method names as well, import the SDKs' compatibility layer,
which calls `/v1/systemone` and returns Jev's shapes; the port is the import
line alone:

```python
from hanzo_kai.jev import Choice, Noul, Score, Client as TypeSafeClient
```

```ts
import { choice, noul, score, Client as TypeSafeClient } from "@hanzo/kai/jev";
```

The full surface: [Python](/docs/kai/sdk/python) and
[TypeScript](/docs/kai/sdk/typescript).

## From OpenRouter

The Jev column is OpenRouter's wire as the benchmark harness called it for
11,099 questions
([`three_way.py`](https://github.com/hanzoai/benchmarks/blob/c61361f/decision/harness/three_way.py));
the Kai column is what `api.hanzo.ai` answers.

| | Jev on OpenRouter | Kai on Hanzo |
|---|---|---|
| Endpoint | `POST https://openrouter.ai/api/alpha/decisions` | `POST https://api.hanzo.ai/v1/decisions` |
| Key | an OpenRouter key | a Hanzo secret key, `sk-` |
| `model` in the request | `typesafe/jev-1.13` | `kai` |
| `model` in the answer | the dated snapshot that served, `typesafe/jev-1.13-20260917` in the harness's run | `kai`; the checkpoint is `routing.checkpoint`, `a7` |
| `id` | OpenRouter's | `dec_` and 32 hex digits |
| `provider` | the provider OpenRouter routed to | `Hanzo` |
| `usage.output_tokens` | as OpenRouter counts them, not billed | `0`: Kai generates nothing |
| `usage.cost` | the call's price in dollars | not sent: `usage.input_tokens` is billed at \$0.021 per million, one row per call in `GET /v1/billing/usage` |
| Fields only Hanzo sends | none | `answer_confidence` on each answer; `routing`, `state_hash` and `latency_ms` on the response ([Decisions](/docs/decisions#response)) |

## What stays the same

- **The request**: `model`, `state` and `questions`, and the optional
  `provider`, `session_id`, `user` and `trace`. Kai accepts the optional four
  and uses none of them.
- **The questions**: `choice`, `noul` and `score`, each with `type`,
  `criteria` and optional `instructions`. A choice maps each label to its
  description, a noul may describe `true` and `false`, a score lists its levels
  lowest first. Instructions, labels, levels and sides may be text, a JSON
  object or an array on both.
- **The answers**: `choice`, `noul`, `score`, `confidence`, `probabilities` and
  `legend`, under the names you gave. On `/v1/systemone` each answer is Jev's
  shape exactly, with `confidence` computed as Jev computes it. On
  `/v1/decisions` a choice's or a score's `confidence` is
  `(n·p_max − 1)/(n − 1)` and a noul's is `|2p − 1|`, and every answer adds
  `answer_confidence`, the probability of the reported answer. Either way the
  numbers are Kai's own calibration: tune thresholds again on your outcomes.
- **`usage.input_tokens`** and **`usage.output_tokens`**.

## What to check

- **Reach is refused, never cut.** Kai reads a state together with each
  question; when a state and any one question do not fit what the served
  checkpoint reads, the call is refused with `422` and `"code":
  "state_too_long"`, naming the tokens needed and the limit. An option (a label
  with its description, a score level, a noul side) is read whole up to 512
  tokens; a longer one is refused with `422` and `"code": "option_too_long"`.
  A question over half of what the checkpoint reads is refused with
  `"code": "question_too_long"`, and a body over 16 MiB with
  `"code": "request_too_long"`. Jev's window is 32,000 tokens, so a long
  document that Jev answered may need to be split, or its deciding part sent
  alone, on Kai.
- **Every score level needs a description**; a `null` level is refused.
- **Phrase a noul as a statement and give both sides in `criteria`, or ask a
  choice whose labels name the outcomes.** The current checkpoint answers
  bare question-form nouls poorly on everyday text ([Limits](/docs/kai/limits)).
- **Limits**: 1 to 100 questions a call. On `/v1/systemone` a choice takes up
  to 255 labels and a score up to 10 levels, as on Jev; on `/v1/decisions`
  neither is capped, since a wide choice is narrowed by retrieval over every
  option ([more than 255 options](/docs/kai/programs/options)). A key over its
  rate gets `429` with `Retry-After` and `retry-after-ms`
  ([errors](/docs/decisions#errors)).
- **Tokens are Kai's own.** `usage.input_tokens` counts the request's text once
  (the state once, each question once) in Kai's tokenizer, which is not Jev's.
- **Self-hosting**: Kai runs at `api.hanzo.ai` only; its weights and runtime
  are not published.
- **Jev itself** stays reachable under its vendor-named ids,
  `typesafe/jev-1.13` and `~typesafe/jev-latest`, on both paths: forwarded to
  OpenRouter and billed at Jev's list price, \$0.042 per million input tokens
  ([pricing](/docs/decisions#pricing)). No Jev id is ever answered by Kai.

## Price and accuracy

**Price**: 50% lower input-token list price (\$0.021 vs \$0.042 per 1M). Output
is free on both. Kai's rate is its row in `GET https://api.hanzo.ai/v1/models`
(`pricing.input` 0.021); each call is a row in `GET /v1/billing/usage`.

**Accuracy**: on the frozen decision harness Kai (checkpoint a7) is more
accurate than Jev on 11 of 12 suites; Jev leads jailbreak detection, 0.940 to
0.920 ([kai-a7](https://github.com/hanzoai/benchmarks/tree/c61361fedc5882b0d83b2f5d5a6a35c56ffeb3c3/decision/results/kai-a7),
[suite by suite](/docs/models/kai#results)). Kai's probabilities are less well
calibrated than Jev's on four suites (expected calibration error, Kai against
Jev): typed decisions 0.172 against 0.047, toxicity 0.191 against 0.177,
jailbreak 0.072 against 0.047 and Banking77 0.076 against 0.073. A threshold
tuned on Jev's `confidence` is to be tuned again.
