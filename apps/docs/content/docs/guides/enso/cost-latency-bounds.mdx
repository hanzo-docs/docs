**Never let a single interactive endpoint blow its latency SLO or unit-economics budget.** Pass `X-Max-Cost` and `X-Max-Latency-Ms` on any routed call — Enso narrows eligible models before selecting a rung.

## Architecture & contract

Org-level defaults live in `GET /v1/ai/org/settings`, and per-request headers always win when stricter. The rewrite happens before provider, pricing, and billing resolve, so the bill always matches the bounded model that served the request.

**Primary endpoint:** `POST /v1/chat/completions` · **Status:** `shipped` · **Level:** `practitioner`

const res = await fetch('https://api.hanzo.ai/v1/chat/completions', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.HANZO_API_KEY}`,
    'Content-Type': 'application/json',
    'X-Max-Cost': '0.002',
    'X-Max-Latency-Ms': '1500',
  },
  body: JSON.stringify({
    model: 'auto',
    messages: [{ role: 'user', content: 'Summarize this release note in one sentence.' }],
  }),
});
console.log('Routed:', res.headers.get('x-routed-model'), await res.json());

## Verify the outcome

- Verify `X-Routed-Model` matches `body.model` and its rate in `/v1/models` sits below your `X-Max-Cost` ceiling.

## Production guardrails

- Avoid setting `X-Max-Cost` below every enabled model in your org; check `/v1/models` first to verify eligible floors.
