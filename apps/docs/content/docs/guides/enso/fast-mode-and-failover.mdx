**Vendor outages should never wake your on-call engineer.** Every Enso tier runs an ordered fallback chain under one model ID and one fixed price, while optional `fast: true` accelerates priority interactive turns.

## Architecture & contract

Failover steps sequentially — the next rung is called only on outage, rate limit, or refusal, never raced redundantly. Fast mode bills from prepaid balance (`2x` on `enso-auto`/`enso-flash`, `3x` on `enso-pro`/`enso-max`, `4x` on `enso-ultra`) and degrades gracefully to standard speed when prepaid balance is zero.

**Primary endpoint:** `POST /v1/chat/completions` · **Status:** `shipped` · **Level:** `practitioner`

## Verify the outcome

- Check `X-Hanzo-Served: enso-pro` and compare time-to-first-token against standard mode.
- Confirm billing balance via `GET /v1/billing/balance`.

## Production guardrails

- Reserve `fast: true` for live user-facing turns; keep background batch and autopilot runs on standard mode to save 2x–4x.
