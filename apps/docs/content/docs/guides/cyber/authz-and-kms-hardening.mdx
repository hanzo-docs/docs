**Zero hardcoded credentials and zero implicit permissions.** Every service and agent verifies access with `POST /v1/authz/check` and reads secrets on demand from Hanzo KMS.

## Architecture & contract

Hanzo IAM authenticates who the principal is; AuthZ decides what `(subject, action, resource)` tuple is permitted; KMS injects scoped secret paths without persisting plaintext on disk; `/v1/audit` records every access.

**Primary endpoint:** `POST /v1/authz/check` · **Status:** `shipped` · **Level:** `architect`

<Tab value="TypeScript">
```ts
import { Configuration, AuthzApi, KmsApi } from 'hanzoai';

const cfg = new Configuration({ accessToken: process.env.HANZO_API_KEY });
const [check, kms] = await Promise.all([
  new AuthzApi(cfg).postAuthzCheck({ subject: 'agent:deploy', action: 'deploy', resource: 'app:billing' }),
  new KmsApi(cfg).getKmsHealth(),
]);
console.log({ allowed: check.data, kms: kms.data });
```

import os
from hanzoai.cloud import ApiClient, Configuration
from hanzoai.cloud.api import AuthzApi, KmsApi

client = ApiClient(Configuration(access_token=os.environ["HANZO_API_KEY"]))
print(AuthzApi(client).post_authz_check({"subject": "agent:deploy", "action": "deploy", "resource": "app:billing"}))
print(KmsApi(client).get_kms_health())

## Verify the outcome

- Verify an unauthorized subject returns `allowed: false` on `POST /v1/authz/check` and the check is logged in `/v1/audit`.

## Production guardrails

- Record KMS secret paths in documentation and runbooks — never log, commit, or echo secret values.
