**Decompose complex workflows into narrow specialist agents instead of one over-privileged monolith.** Each agent carries its own model tier, instructions, run history, and spend budget.

## Architecture & contract

Every agent is addressable by ID or org-unique name (`ref`). Runs execute asynchronously (`POST /v1/agent/{ref}/run`, `GET /v1/agent/{ref}/runs`), while structured work packets travel between specialists over `/v1/agent/a2a`.

**Primary endpoint:** `POST /v1/agent` · **Status:** `shipped` · **Level:** `architect`

import { Configuration, AgentApi } from 'hanzoai';

const agents = new AgentApi(new Configuration({ accessToken: process.env.HANZO_API_KEY }));

  model: 'enso-pro',

## Verify the outcome

- Poll `GET /v1/agent/release-verifier/runs` until the run reaches a terminal status and inspect `GET /v1/agent/activity`.

## Production guardrails

- Give builder agents write access only inside isolated sandboxes or worktrees, and assign review/verification to a separate agent.
