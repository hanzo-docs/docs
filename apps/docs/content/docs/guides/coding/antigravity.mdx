## Set up

```bash
curl -fsSL hanzo.sh | sh
hanzo                  # first run: sign in, link Tabs, pick your agent (choose Antigravity)
hanzo dev --agy          # switch to it later; saved as your favourite
```

`hanzo -- -c` continues the last conversation.

`hanzo dev --agy` runs the Antigravity CLI, `agy`. Install and sign in to it first, as you would to use it alone. `antigravity` is an accepted spelling of `agy`.

## What the wrapper does

Antigravity keeps its own login and its own backend. `hanzo dev --agy` has no gateway route for it, so it always runs on Antigravity's account. The wrapper:

- starts the binary in your repository, with `--dangerously-skip-permissions` so it stops asking before each action; `--ask` leaves its own prompts in place;
- for a task (`hanzo dev --agy "fix the failing test"`), runs it with `--print` and `--output-format stream-json`, and when the session is linked streams the assistant's messages and the final result to the cloud;
- registers the session in the cloud with its machine and directory, and updates its status when the tool exits. An interactive run is Antigravity's own screen, so its events are not streamed;
- passes any other flags through to the tool unchanged.

## What it does not do

- **No routing.** Antigravity's model calls do not go through api.hanzo.ai, and Hanzo does not see them.
- **No metering.** Nothing is counted into your org's usage. The end-of-session block prints the duration and the session link, and says the usage was not observed.
- **No Hanzo toolset.** The Hanzo MCP server and your org's cloud tools are not attached to Antigravity.
- **No resume.** The tool discloses no session id to the wrapper, so `hanzo --resume` has nothing to continue.

## See the session

```bash
hanzo console          # sessions and machines; press 6 for the usage Savings page
```

The Savings page shows your org's usage from other tools, not Antigravity's. [How to read the numbers →](/docs/guides/coding)

## Keep your own plan

There is nothing to turn off: Antigravity already runs on its own. `--no-link` stops the session being shown in the cloud.
