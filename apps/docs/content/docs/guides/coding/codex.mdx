## Set up

```bash
curl -fsSL hanzo.sh | sh
hanzo                  # first run: sign in, link Tabs, pick your agent (choose Codex)
hanzo dev --codex        # switch to it later; saved as your favourite
```

`hanzo -- -c` continues the last conversation.

Give it a task as one quoted argument to run it headless: `hanzo dev --codex "port this module to the new store"`. Codex is its own tool here, never an alias of Hanzo Dev (`hanzo dev`), which shares its driver.

## Which model answers

`hanzo dev --codex` starts Codex on your own login, ChatGPT plan or API key, directly. Nothing is sent through Hanzo by default, and Hanzo meters none of that traffic.

- **Local Zen and Kai.** When Zen or Kai run on this machine, routine turns go to them.
- **Hanzo's cloud models** answer in two cases only: your own account has hit its usage limit, and the run continues on your Hanzo plan until the limit resets; or you pass `--cloud`.

```bash
hanzo dev --codex             # your own account; local Zen and Kai take routine turns
hanzo dev --codex --cloud     # Hanzo's cloud models, on your Hanzo plan
```

## On Hanzo's cloud models

When a run goes to the cloud, with a signed-in account:

- **Model calls** go through Codex's `hanzo` provider at `https://api.hanzo.ai/v1`, with your Hanzo token in `HANZO_USER_KEY`. The model is `enso-auto` unless you set another with `--model` or in `~/.hanzo/settings.json`.
- **Usage** is metered into your org at api.hanzo.ai.
- **The Hanzo toolset** and your org's cloud tools are added as MCP servers through Codex's `-c mcp_servers.*` overrides. Your own `config.toml`, your servers and your `codex login` are untouched, because the wrapper never repoints `CODEX_HOME`.
- **The session** is registered in the cloud and, for a headless run, its events stream there. Pass `--no-link` to keep it local.

## What does not

- Your `config.toml` wins where it sets a value. The wrapper adds `approval_policy` and `sandbox_mode` only when your file leaves them unset, and it keeps the workspace sandbox. `--no-sandbox` drops the sandbox and approvals for one run; `--ask` leaves Codex asking.

## See usage and savings

A linked headless run prints the tokens Codex reported, the cached share and the cost at the listed price when it ends. Any other run on Hanzo's cloud models prints the cloud's count for the session window. Then:

```bash
hanzo console          # press 6 for Savings
hanzo usage summary --range 7d
```

## Keep the session local

Your own account is already the default. `--no-link` is the switch for the session:

```bash
hanzo dev --codex --no-link     # the session is not shown in the cloud
```

Codex keeps its own login, and the wrapper leaves its environment alone. Hanzo's cloud models answer only when your account hits its limit, or when you pass `--cloud`.
