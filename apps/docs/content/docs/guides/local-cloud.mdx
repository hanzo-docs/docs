Run the **exact same Hanzo OSS Cloud** (`ghcr.io/hanzoai/cloud-oss:main`) that powers `api.hanzo.ai` and `platform.hanzo.ai` directly on your laptop, workstation, or private bare-metal server — backed by a warm local `k3s` Kubernetes substrate and the `hanzod` runtime controller.

## Three-Layer Lifecycle Architecture

Hanzo separates **infrastructure substrate**, **platform & project workloads**, and **active coding loops** into three clean CLI layers so stopping one project never tears down your cluster or sister apps:

| Layer | Commands | Scope & Lifecycle |
| --- | --- | --- |
| **1. Infrastructure Substrate** | `hanzo start` · `hanzo stop` · `hanzo restart` | Boots/halts the warm local `k3s` Kubernetes cluster (`hanzoai/vm` on macOS/Windows, native cgroups/containerd on Linux) and `hanzod` daemon. Stays warm across projects. |
| **2. Platform & Project Workloads** | `hanzo up` · `hanzo down` · `hanzo status` | Reconciles `hanzo.yaml` / `compose.yaml` into isolated Kubernetes namespaces (e.g. `hanzo-cloud`, `solar-crm`) so multiple apps run side-by-side without port collisions. |
| **3. Interactive Coding & Models** | `hanzo dev` · `hanzo pull` · `hanzo engine serve` | Runs the terminal coding agent (`hanzoai/dev-v1`) with HIP-0300 MCP tools and optional local `zen6-flash` weights against your local or cloud `/v1` gateway. |

# 1. Install the ~15 MB Rust CLI

# 2. Boot warm k3s substrate + hanzod daemon (idempotent, sub-second once warm)
hanzo start

# 3. Bring up the full OSS Cloud control plane (IAM, KMS, Base, KV, Vector, PubSub, Gateway)
hanzo up --cloud

hanzo status

## 2. Run Multi-Project Apps Side-by-Side (`Cloud` + `Solar CRM`)

Because `hanzo up` scopes every repository to its own Kubernetes namespace and ingress hostname on the shared warm `k3s` cluster, you can run `ghcr.io/hanzoai/cloud-oss:main` alongside business apps (like Solar CRM, Commerce, or Studio) and tear down one without disturbing the others:

```bash
# Terminal 1: Keep Hanzo OSS Cloud running in namespace `hanzo-cloud`
cd ~/work/hanzo/cloud && hanzo up

# Terminal 2: Boot a multi-service app in its own isolated namespace `solar-crm`
cd ~/work/solar-crm && hanzo up

# Tear down ONLY solar-crm — `hanzo-cloud` and warm k3s stay online!
cd ~/work/solar-crm && hanzo down

# Halt the entire local k3s VM/substrate when finished for the day
hanzo stop
```

## 3. Declarative `hanzo.yaml` Workload Contract

Drop a `hanzo.yaml` at the root of any repository so `hanzo up` locally and `hanzo deploy` in production reconcile the exact same services, secrets, and `/v1` bindings:

```yaml title="hanzo.yaml"
name: solar-crm
org: acme

services:
  web:
    build: ./apps/web
    port: 3000
    env:
      NEXT_PUBLIC_HANZO_URL: ${HANZO_BASE_URL}
  worker:
    build: ./services/worker
     subscribe: ["crm.leads.*"]

capabilities:
  iam: true
  kms: true
  base: true
  kv: [sessions]
  pubsub: [crm]
```
