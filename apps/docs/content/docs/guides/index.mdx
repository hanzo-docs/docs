One key authenticates every request across our cloud (`https://api.hanzo.ai/v1`) and your own self-hosted OSS Cloud (`hanzo up`). `sk-` keys resolve to a user or service and belong on a server; `pk-` keys resolve only to an organisation and are safe in a browser.

```bash
export HANZO_API_KEY=sk-...     # platform.hanzo.ai/api-keys
hanzo auth login                # or sign in through Hanzo IAM (hanzo.id)
```

## Five Surfaces, One `/v1` Contract

Every capability in Hanzo OSS Cloud is generated from one OpenAPI specification, so what you learn on one surface holds across all five:

| Surface | How You Reach It |
| --- | --- |
| **App & Desktop** | [hanzo.app](https://hanzo.app), [platform.hanzo.ai](https://platform.hanzo.ai), and [Hanzo Desktop](/docs/apps/desktop) |
| **CLI & Local Cloud** | `hanzo start`, `hanzo up`, `hanzo dev`, and `hanzo <capability> <verb>` |
| **SDKs** | Typed clients in TypeScript, Python (`hanzoai>=8`), Go (`/v8`), Rust, C#, C++, Swift & Kotlin |
| **HTTP `/v1/*`** | `https://api.hanzo.ai/v1/<capability>` (or `http://localhost:8000/v1/<capability>`) |
| **HIP-0300 MCP** | 19 local operator tools (`npx -y @hanzo/mcp serve`) + hosted `POST /v1/mcp` |
