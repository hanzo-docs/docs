**Monetize air-gapped and on-premise deployments without phone-home telemetry.** `/v1/licensing` issues asymmetric signed license tokens your binary can verify completely offline against your public key or JWKS.

## Architecture & contract

Issue signed entitlements containing org, seat/GPU caps, and expiry via `POST /v1/licensing/issue`. Ship the matching public key (`GET /v1/licensing/pubkey` or `/v1/licensing/jwks`) inside your self-hosted binary for zero-egress verification.

**Primary endpoint:** `POST /v1/licensing/issue` · **Status:** `shipped` · **Level:** `architect`

import { Configuration, LicensingApi } from 'hanzoai';

const lic = new LicensingApi(new Configuration({ accessToken: process.env.HANZO_API_KEY }));

  lic.getLicensingPubkey(),
  lic.getLicensingReleases(),

<Tab value="HTTP">
```bash
# Retrieve public verification key & JWKS
curl -s https://api.hanzo.ai/v1/licensing/pubkey \
  -H "Authorization: Bearer $HANZO_API_KEY" | jq '.'

# Verify a presented license token
curl -s -X POST https://api.hanzo.ai/v1/licensing/verify \
  -H "Authorization: Bearer $HANZO_API_KEY" -H "Content-Type: application/json" \
  -d '{"license":"<signed-license-token>"}' | jq '.'
```

## Verify the outcome

- Verify a newly issued license validates cleanly both via `POST /v1/licensing/verify` and offline against `GET /v1/licensing/pubkey`.
