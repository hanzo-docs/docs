Every layer of the Hanzo AI Operating System is built in the open across **Go** (control plane, IAM, KMS, Base, Commerce, Gateway) and **Rust** (CLI, inference engine, coding agent, microVM hypervisor, VFS, ZAP wire protocol) — speaking HTTP `/v1/*` and zero-copy [ZAP](/docs/zap) across boundaries, never brittle cross-language FFI.

## Canonical Repository `Makefile` Contract

Every core `hanzoai/*` repository implements the same standard `Makefile` targets so contributors, interns, and autonomous coding agents can boot, test, and ship any service without guessing flags:

```bash
make up       # Reconcile local dependencies & start service on warm k3s (`hanzo up`)
make down     # Tear down this repo's namespace cleanly without stopping sister repos
make dev      # Run hot-reloading local development loop against local OSS Cloud
make test     # Execute unit + integration test suites deterministically
make lint     # Static analysis, formatting, and OpenAPI / schema contract checks
```

## 5-Minute Contributor & Local OS Setup

```bash
# 1. Install the Hanzo CLI + Dev agent + MCP server
curl -fsSL https://hanzo.sh | sh

# 2. Boot warm k3s substrate + local OSS Cloud (`ghcr.io/hanzoai/cloud-oss:main`)
hanzo start
hanzo up --cloud

# 3. Clone any OSS subsystem (from GitHub or forge.hanzo.ai) and hack locally
git clone https://github.com/hanzoai/cloud.git ~/work/hanzo/cloud
cd ~/work/hanzo/cloud
make dev

# 4. Let Hanzo Dev implement, test, and verify changes against your local cloud
hanzo dev "add integration test for /v1/kv bucket TTL expiration and run make test"
```
