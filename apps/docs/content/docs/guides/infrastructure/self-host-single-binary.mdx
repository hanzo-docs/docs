**The hosted cloud and the binary you run on your own metal are the same software.** Self-host `hanzoai/cloud` for air-gapped, sovereign, or zero-egress environments with identical SDKs and CLI commands.

## Architecture & contract

One Go binary bundles Base, KMS hooks, PubSub/JetStream, and API routing with zero mandatory external Postgres or Redis during local boot. For multi-node Kubernetes clusters, `hanzo up` provisions a Dockerless local microVM k3s cluster.

**Primary endpoint:** `GET /v1/models` · **Status:** `shipped` · **Level:** `practitioner`

## Run it across all four surfaces

<Tabs items={['CLI', 'SDK', 'HTTP', 'MCP']}>
<Tab value="CLI">
```bash
git clone https://github.com/hanzoai/cloud && cd cloud
make dev
# Verify local health and models endpoint
curl -sS http://127.0.0.1:9090/healthz
```
</Tab>
<Tab value="SDK">
<Tabs items={['TypeScript', 'Python']}>
<Tab value="TypeScript">
```ts
import { Configuration, AiApi } from 'hanzoai';

const local = new AiApi(new Configuration({
  basePath: 'http://127.0.0.1:8080',
  accessToken: process.env.HANZO_API_KEY,
}));
const { data } = await local.getModels();
console.log(data);
```
</Tab>
<Tab value="Python">
```python
import os
from hanzoai.cloud import ApiClient, Configuration
from hanzoai.cloud.api import AiApi

client = ApiClient(Configuration(host="http://127.0.0.1:8080", access_token=os.environ["HANZO_API_KEY"]))
print(AiApi(client).get_models())
```
</Tab>
</Tabs>
</Tab>

```bash
    }
  }'
```

## Verify the outcome

- Verify `http://127.0.0.1:9090/healthz` returns HTTP 200 and a local `/v1/base` write persists across restarts.

## Production guardrails

- Keep root disk usage below 85% on self-hosted nodes and back up encrypted KMS root keys out of band.
