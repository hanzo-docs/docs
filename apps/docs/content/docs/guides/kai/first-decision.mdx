**Replace fragile JSON-from-LLM classification with one calibrated forward pass.** Kai scores bounded options directly on CPU with `usage.output_tokens == 0`, costing `$0.021` per million input tokens.

## Architecture & contract

Kai reads your `state` beside each question independently: `choice` picks one label with a normalized distribution, `noul` returns `P(true)`, and `score` computes an ordinal expectation over ordered criteria. Because options are scored independently, shuffling label order never changes probabilities.

**Primary endpoint:** `POST /v1/decisions` · **Status:** `shipped` · **Level:** `foundations`

## Verify the outcome

- Assert `usage.output_tokens == 0`.
- Assert `answers.team.choice == "billing"` and `answers.team.probabilities` sums to `1.0`.
- Record `id`, `state_hash`, and `routing.calibration` for downstream auditing.

## Production guardrails

- Keep `state` plus each question under `1,024` tokens (`routing.extrapolated == false`) for peak calibration; reads beyond `32,768` tokens fail with `422 state_too_long`.
- Use `sk-` server keys; `pk-` publishable keys return `403`.
