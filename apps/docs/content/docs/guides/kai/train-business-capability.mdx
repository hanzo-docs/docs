**Companion 4-surface lab for [KAI 301 Lab 01: Teach Kai your business](/docs/training/kai-capabilities).** Turn domain corrections into a tenant-private Kai capability in seconds on CPU with zero re-encoding and bit-for-bit invariance on unrelated questions.

## Architecture & contract

`POST /v1/capabilities/{name}/train` fits the smallest correction that clears held-out evaluation against base Kai (**calibration → linear head → boost+veto pair**). Published capabilities attach strictly behind their exact `(question_key, type, labels)` route and support instant artifact rollback.

**Primary endpoint:** `POST /v1/capabilities/{name}/train` · **Status:** `shipped` · **Level:** `specialist`

## Run it across all four surfaces

<Tabs items={['CLI', 'SDK', 'HTTP', 'MCP']}>
<Tab value="CLI">
```bash
# 1. Enable state capture and inspect captured corrections
hanzo capabilities capture replace --data '{"enabled":true}'
hanzo capabilities corrections

# 2. Create draft capability bound to one question route and train on CPU
hanzo capabilities create --data '{"name":"billing-refund-router","question":"refund_route"}'
hanzo capabilities train billing-refund-router

# 3. Inspect held-out evaluation report and publish if gate passed
hanzo capabilities get billing-refund-router
hanzo capabilities publish billing-refund-router
```

## Verify the outcome

- Confirm `GET /v1/capabilities/billing-refund-router` shows `repaired > damaged`, passing calibration, and `100%` bit-for-bit invariance on unrelated questions.
- Test an adversarial prompt-injection state and verify policy floors remain intact.

## Production guardrails

- Never force a failing version into production — `POST /v1/capabilities/{name}/publish` rejects non-passing versions with `409 not_publishable`.
- If base Kai upgrades, re-run `/train` to clear `409 needs_validation`.
