**Treat org-private Kai capabilities like production code deployments: retrain on a schedule, inspect held-out metrics in CI, publish atomically, and roll back in one API call if live drift appears.**

## Architecture & contract

While `POST /v1/capabilities/{name}/train` trains a candidate version, the currently installed version keeps answering live org traffic untouched. `POST /v1/capabilities/{name}/publish` atomically swaps traffic only if the candidate passed evaluation on the active base Kai checkpoint; `POST /v1/capabilities/{name}/rollback` restores the exact prior artifact without retraining.

**Primary endpoint:** `POST /v1/capabilities/{name}/publish` · **Status:** `shipped` · **Level:** `specialist`

## Verify the outcome

- Trigger `rollback` and confirm `GET /v1/capabilities/billing-refund-router` reports the prior version active immediately.
- Trigger `disable` and confirm base Kai answers bit-for-bit on the very next decision.

## Production guardrails

- Handle `409 no_previous` gracefully when rolling back a capability that only ever published version 1 (use `/disable` instead).
- Keep `DELETE /v1/capabilities/{name}` blocked until `/disable` runs first.
