**Prove that a model or prompt upgrade moves real user metrics before rolling it to 100% of traffic.** `/v1/experiment` separates deterministic assignment, statistical analysis, and audited winner promotion.

## Architecture & contract

`assign` is a pure read that hashes `(experiment_id, subject)` consistently; your app logs an exposure event on `/v1/event` only when the user actually triggers the code path. `analyze` computes lift without mutating flags; `decide` atomically sets the winner to 100% and stamps the deciding principal.

**Primary endpoint:** `POST /v1/experiment` · **Status:** `shipped` · **Level:** `practitioner`

<Tab value="HTTP">
```bash
EXP_ID=$(curl -s -X POST https://api.hanzo.ai/v1/experiment \
  -H "Authorization: Bearer $HANZO_API_KEY" -H "Content-Type: application/json" \
  -d '{"name":"kai-triage-rollout","variants":[{"key":"control","weight":50},{"key":"kai_v2","weight":50}]}' | jq -r '.id')

curl -s "https://api.hanzo.ai/v1/experiment/${EXP_ID}/assign?subject=org_123" \
  -H "Authorization: Bearer $HANZO_API_KEY" | jq '.'

curl -s -X POST "https://api.hanzo.ai/v1/experiment/${EXP_ID}/analyze" \
  -H "Authorization: Bearer $HANZO_API_KEY" | jq '.'
```

## Verify the outcome

- Verify `decide` stamps winner, credential, and timestamp.
