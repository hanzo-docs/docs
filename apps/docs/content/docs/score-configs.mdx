# Score Configs

A rubric is the schema for a [score](/docs/scores): its data type, and its valid
range or set of categories. Rubrics are what keep a metric meaning the same thing
across runs — a `helpfulness` score always on 1–5, a `sentiment` score always
using the same labels.

## Declare one

```bash
curl -X POST https://api.hanzo.ai/v1/evals/rubrics \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "helpfulness",
    "dataType": "NUMERIC",
    "minValue": 1,
    "maxValue": 5
  }'
```

The `name` is the key: writing the same name again edits the rubric rather than
creating a second one.

## Data types

| `dataType` | Constraint fields | Use for |
|------------|-------------------|---------|
| `NUMERIC` | `minValue`, `maxValue` | Ratings and rubric scores (1–5, 0.0–1.0) |
| `CATEGORICAL` | `categories` | Labeled buckets |
| `BOOLEAN` | — | Pass/fail checks. The value must be exactly `0` or `1` |

`NUMERIC` is the default. `categories` is a plain list of strings:

```bash
curl -X POST https://api.hanzo.ai/v1/evals/rubrics \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "sentiment",
    "dataType": "CATEGORICAL",
    "categories": ["positive", "neutral", "negative"]
  }'
```

Categories are trimmed and de-duplicated, capped at 64 per rubric and 256
characters each. A `CATEGORICAL` rubric with no categories, a non-finite bound,
or `minValue` above `maxValue` is rejected with `400`.

## What a rubric enforces

Once declared, the rubric is authoritative at write time. It overrides whatever
`dataType` the writer claims, so the same metric name cannot arrive as a number
from one caller and a string from another. A value outside the bounds, or a
category not in the set, is refused rather than stored.

## List them

```bash
curl https://api.hanzo.ai/v1/evals/rubrics \
  -H "Authorization: Bearer $HANZO_API_KEY"
```
