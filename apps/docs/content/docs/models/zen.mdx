**After this page you know which Zen model does which job, how to call it,
where its weights are, and which generation is current.**

Zen is the open-weight generative family of Zen LM, from [Zoo Labs Foundation](https://zoo.ngo), a
501(c)(3) non-profit, and served on `api.hanzo.ai`. It is chosen for two jobs.

**Agentic coding that runs locally.** `zen6` is a 27B dense model that reads
262,144 tokens natively and 1,048,576 with YaRN, and ships a speculative drafter
for faster decoding; its card reports 141 tokens a second on code completion on
one DGX Spark. `zen6-flash` is the same generation in ternary weights, 5.95 GB,
for an Apple Silicon laptop or one GPU. Hosted, both ids take a 1,000,000-token
context.

**Marketing work.** [`POST /v1/content/generate`](/docs/openapi/content/post-content-generate) drafts
campaigns and social posts from a brief, with the brand-voice guidance you pass
and the Zen model you name, and files each one in the CMS as a draft. `zen6`
reads images and video beside the brief, and `zen-vl` reads images, documents
and charts. The Zen 3 weights make the images
(`zen3-image`) and speech (`zen3-tts`) that go with the copy.

Weights are published under [huggingface.co/zenlm](https://huggingface.co/zenlm); each model card states its
license, base and serving instructions. The same ids answer hosted on
`api.hanzo.ai`.

## Generations

| Generation | Models | Where | Status |
|---|---|---|---|
| **Zen 7** | — | no weights; no id to call | research preview · [Request access](https://hanzo.ai/research-access) · succeeds Satori |
| **Zen 6** | `zen6`, and `zen6-flash`, its ternary build | hosted; weights at [`zenlm/zen6`](https://huggingface.co/zenlm/zen6) and [`zenlm/zen6-flash`](https://huggingface.co/zenlm/zen6-flash) | available now |
| **Zen 5** | `zen5`, `zen5-coder`, `zen5-flash`, `zen5-mini`, `zen5-pro`, `zen5-evo`, `zen5-spark` | hosted; GGUF builds on Hugging Face (`zen5-gguf`, `zen5-coder-gguf`, …) | earlier |
| **Zen 3** | speech (`zen3-asr`, `zen3-tts`), image (`zen3-image`), `zen3-vl`, `zen3-omni`, `zen3-nano`, `zen3-guard` | weights on Hugging Face | shipped |

Task lines sit beside the generations: `zen-embedding` and `zen-reranker`
(0.6B, 4B, 8B) for retrieval, `zen-guard` for safety, `zen-vl`
for vision. `zen-free` and `hanzo/zen` answer on the gateway too.
[`zen-router`](https://huggingface.co/zenlm/zen-router) is a
classifier, not a generator; the gateway also accepts its name as an alias for
[`auto`](/docs/models/enso).

## Call one

```bash
curl https://api.hanzo.ai/v1/chat/completions \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "zen6",
    "messages": [{"role": "user", "content": "Write a binary search in Rust."}]
  }'
```

Every hosted Zen id, with its context window and rate, is one request away and
needs no key:

```bash
curl -s https://api.hanzo.ai/v1/models \
  | jq -r '.data[] | select(.owned_by == "zenlm") | "\(.id)\t\(.context_window)\t\(.pricing.input)/\(.pricing.output)"'
```

The gateway is the source of truth for ids, windows and rates. If this page and
that command disagree, believe the command.

## Run one yourself

```bash
hf download zenlm/zen6 --local-dir zen6
hf download zenlm/zen6-flash --local-dir zen6-flash
```

Each card carries the serving command its model was built for: SGLang for
`zen6`, llama.cpp for `zen6-flash` and the GGUF builds. A server that speaks
`/v1/chat/completions` takes the same request as above with its own base URL.

## Where Zen sits

Zen is the model that writes. It is not the model that picks which model
writes — that is [Enso](/docs/models/enso) — and it is not asked bounded
questions a typed answer settles — that is [Kai](/docs/models/kai). An agent
built on all three spends generative compute only where generation is the work.

Specifications: [HIP-0039](https://hips.hanzo.ai/docs/hip-0039-zen-model-architecture) for the
family; [HIP-0904](https://hips.hanzo.ai/docs/hip-0904-zen6) records what each `zenlm/zen6*`
repository on Hugging Face holds.
