Ayrshare takes text and media, and puts it on the networks you have connected.
`/v1/social` (13 operations) covers the same ground: the accounts an org has
connected, the posts it holds, and publishing one.

## Nouns

| Ayrshare | Hanzo |
|---|---|
| `POST https://api.ayrshare.com/api/post` | `POST /v1/social/posts` |
| `post` | `content` — required, capped at 8192 characters |
| `platforms: ["twitter", "linkedin"]` | `channel` — one of `x`, `facebook`, `instagram`, `linkedin`, `tiktok`, `youtube`, `threads` |
| `mediaUrls` | `media` — up to 10 URLs, each capped at 1024 characters |
| `scheduleDate` | `scheduleAt` — a unix second; `0` leaves the post a draft |
| Publishing something already stored | `POST /v1/social/posts/{id}/publish` |
| `/api/history` | `GET /v1/social/posts`, narrowed by `?status=` |
| Deleting a post | `DELETE /v1/social/posts/{id}` |
| Connected profiles | `GET /v1/social/accounts` · `POST /v1/social/accounts` — `provider`, `handle`, `status` |
| Whether a network can be used at all | `GET /v1/social/providers` |
| User Profiles, one per end customer | The org in the key |
| Post id used for later calls | `id` on the row, and the network's own id in `externalId` |

`status` is one of `draft`, `scheduled`, `published` or `failed`, and it defaults
to `draft`.

## The call

Ayrshare — one call, several networks:

```bash
curl -X POST https://api.ayrshare.com/api/post \
  -H "Authorization: Bearer $AYRSHARE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "post": "Today is a great day!",
    "platforms": ["twitter", "facebook", "instagram", "linkedin"],
    "mediaUrls": ["https://img.ayrshare.com/012/gb.jpg"]
  }'
```

Hanzo — one call per network, then publish:

```bash
POST_ID=$(curl -sS -X POST https://api.hanzo.ai/v1/social/posts \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "content": "Today is a great day!",
    "channel": "linkedin",
    "media": ["https://example.com/gb.jpg"]
  }' | jq -r .id)

curl -sS -X POST "https://api.hanzo.ai/v1/social/posts/$POST_ID/publish" \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

Publishing is idempotent. A post that has already published, or that another
caller is publishing right now, comes back unchanged rather than being posted
twice — and the claim is taken before any network call, which is what makes a
double submit safe.

To schedule instead, set `status` to `scheduled` and `scheduleAt` to the unix
second you want. A time that has already passed publishes immediately and the
returned row carries that outcome.

Before either, check what the deployment can actually do:

```bash
curl -sS https://api.hanzo.ai/v1/social/providers \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

It reports each network's publish-readiness — whether the OAuth application
credentials are held and, when they are not, exactly which environment variables
are missing. It says nothing about whether *you* have connected an account;
that is `GET /v1/social/accounts`.

## What does not carry

**One post, one network.** `platforms` is an array; `channel` is a string, and a
post names exactly one. Fanning out to four networks is four posts. That is more
calls, but it also means one network failing is one row marked `failed` with its
reason, not a partial success you have to unpack.

**No per-network options.** Ayrshare carries `twitterOptions`, `youTubeOptions`,
`instagramOptions` and the rest for thread splitting, titles, first comments,
reels. There is no options object.

**No analytics and no comments.** Post analytics, comment reading and comment
posting have no counterpart. What comes back after a publish is the account it
went through, the network's `externalId`, and a `failed` reason if there was one.

**No User Profiles.** Ayrshare's Business plan keys posts to a profile per end
customer so an agency can post on many clients' behalf. The tenant here is the
org in the key, and there is no profile below it.

**No idempotency key on create.** Publishing is idempotent; creating is not.
A retried create makes a second row.

**Two failure shapes, on purpose.** Having no connected account for the channel
is yours to fix, so it is recorded *on* the post as `failed` with the reason and
answers normally. A deployment that lacks the network's own credentials cannot
publish for anyone, so that is a 503 naming exactly what is missing.
