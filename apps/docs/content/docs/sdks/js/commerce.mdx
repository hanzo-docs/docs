# commerce.js

The Hanzo Commerce API client — billing, subscriptions, payments, and usage tracking. Vanilla JS/TS, no framework dependencies; it runs in the browser, Node.js, and edge runtimes. `commerce.js` is a thin, unscoped re-export of [`@hanzo/commerce`](https://www.npmjs.com/package/@hanzo/commerce)'s `client` entrypoint, so you can use the commerce client without scoped imports.

```bash
npm install commerce.js
```

## Quick start

```ts
import { Commerce } from 'commerce.js'

const commerce = new Commerce({
  baseUrl: 'https://api.hanzo.ai', // default
  token: accessToken,              // @hanzo/iam access token
})

// Billing
const balance = await commerce.getBalance('hanzo/alice')
const tier = await commerce.getTier('hanzo/alice')

// Usage metering
await commerce.addUsageRecord({ user: 'hanzo/alice', currency: 'usd', amount: 12 })

// Subscriptions
await commerce.subscribe({ planId: 'growth', userId: 'hanzo/alice' })
```

## Client

`Commerce` talks to the Hanzo API at `https://api.hanzo.ai` (override with `baseUrl`). Requests authenticate with an [`@hanzo/iam`](/docs/sdks/iam) access token passed as `token`, or refreshed later via `commerce.setToken(...)`. Billing and usage endpoints live under `/v1/billing/*`; checkout, coupons, referrals, and affiliates under their own `/v1/*` groups.

Covered surface: balances & tiers, usage records, deposits & credits, plans, subscriptions, checkout sessions, payment methods, card tokenization, coupons, referrals, affiliates, and wallet/crypto top-ups.

## Errors

Failed requests throw `CommerceApiError`, which carries the HTTP `status`:

```ts
import { Commerce, CommerceApiError } from 'commerce.js'

try {
  await commerce.getBalance('hanzo/alice')
} catch (err) {
  if (err instanceof CommerceApiError) console.error(err.status)
}
```
