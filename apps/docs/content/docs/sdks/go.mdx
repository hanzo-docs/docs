# Go

```bash
go get github.com/hanzoai/go-sdk
```

```go
import "github.com/hanzoai/go-sdk" // package hanzoai
```

The package name is `hanzoai` and it sits at the module root, beside `go.mod` —
which is why the import path and the package identifier differ. The module path
stays `github.com/hanzoai/go-sdk` permanently: it is what the module proxy has
and what existing code requires. The source lives at
[hanzo-go/sdk](https://github.com/hanzo-go/sdk).

Set the key:

```bash
export HANZO_API_KEY="sk-..."   # from console.hanzo.ai
```

## The shape

One configuration, one client, one service field per capability:

```go
package main

import (
    "context"
    "fmt"
    "os"

    "github.com/hanzoai/go-sdk"
)

func main() {
    cfg := hanzoai.NewConfiguration()
    cfg.AddDefaultHeader("Authorization", "Bearer "+os.Getenv("HANZO_API_KEY"))
    client := hanzoai.NewAPIClient(cfg)

    models, _, err := client.ModelsAPI.AiListModels(context.Background()).Execute()
    if err != nil {
        panic(err)
    }
    fmt.Println(models)
}
```

Every operation is a request builder: the method takes a `context.Context` and
returns a request you finish with `.Execute()`, which answers the decoded value,
the `*http.Response` and an error. Optional parameters are setters on the
request in between.

The service field is the capability — `client.ModelsAPI`, `client.BillingAPI`,
`client.KmsAPI` — and the method is the operation. The
[reference](/docs/openapi) prints the pair for each one.

<Callout title="OpenAI-shaped calls">
The chat, embeddings and messages routes speak the OpenAI and Anthropic wire
formats, so an existing Go client for either works against
`https://api.hanzo.ai/v1` with a Hanzo key. This client adds the rest of `/v1`.
</Callout>
