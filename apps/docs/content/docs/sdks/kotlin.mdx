# Kotlin

Generated from the API's own document onto OkHttp and Gson — the same HTTP and
JSON stack the [Java](/docs/sdks/java) client uses, so a JVM project pulling
both pulls one stack.

<Callout title="Not on Maven Central yet">
`ai.hanzo:hanzo-kotlin-cloud` resolves from no repository. Build it into your
local Maven repository, or use the [Java](/docs/sdks/java) client, which is on
Maven Central, from Kotlin.
</Callout>

## Install

Building wants a JDK 21 toolchain; the jar is Java 8 bytecode. `-PpublishLocal`
skips the GPG signing a Central upload needs.

```sh
git clone https://github.com/hanzo-kotlin/sdk hanzo-kotlin-sdk
cd hanzo-kotlin-sdk
./gradlew -PpublishLocal :hanzo-kotlin-cloud:publishToMavenLocal
```

```kotlin
// build.gradle.kts
repositories { mavenLocal() }
dependencies { implementation("ai.hanzo:hanzo-kotlin-cloud:8.5.156") }
```

## The shape

`Hanzo()` reads the endpoint and the credential from the environment
(`HANZO_API_KEY`, `HANZO_BASE_URL`, default `https://api.hanzo.ai`), and
`api(::SomeApi)` builds any generated class against them:

```kotlin
import ai.hanzo.Hanzo
import ai.hanzo.cloud.api.KeysApi

fun main() {
    val keys = Hanzo().api(::KeysApi).getKeys().propertyKeys.orEmpty()
    println("${keys.size} keys")
}
```

The classes follow the document's tags under `ai.hanzo.cloud.api`, with their
request and response types under `ai.hanzo.cloud.model`, so the
[reference](/docs/openapi) is the index. Calls block; wrap them in your own
dispatcher if you need them off a thread.
