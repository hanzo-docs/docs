## Contributing to Hanzo Dev

We welcome bug reports, pull requests, and improvements to [`hanzoai/dev`](https://github.com/hanzoai/dev). For general contributor onboarding across all Hanzo repositories, HIPs, and documentation, see [Contributing](/docs/contributing).

- **Community & questions**: Join [Hanzo Discord](https://discord.gg/XthHQQj) (`#general` and `#docs`).
- **Bounties & rewards**: Merged contributions earn points on [hanzo.ai/bounty](https://hanzo.ai/bounty) and [hanzo.ai/leaderboard](https://hanzo.ai/leaderboard).
- **Bug reports**: Run `/feedback` directly inside the `dev` TUI or open an issue on [`hanzoai/dev`](https://github.com/hanzoai/dev/issues) with reproduction steps.

## Development Workflow

1. Fork [`hanzoai/dev`](https://github.com/hanzoai/dev) and create a topic branch from `main`.
2. Initialize the engine submodule:
   ```bash
   git submodule update --init --depth 1
   ```
3. Keep changes focused and atomic — every commit should compile cleanly with zero warnings and pass the test suite.

### Running Checks

```bash
make build          # build the dev binary (must pass with zero warnings)
make test           # run the Hanzo test suite
make test-upstream  # run the engine test suite
```

### Architecture & Boundaries

- `crates/hanzo-dev` is the binary entry point (`dev`).
- `crates/hanzo-config` manages configuration, provider selection, and `~/.hanzo/dev`.
- `crates/hanzo-tui` provides Hanzo account integration (`/login`, `/logout`, `/auth`, `/status`).
- `crates/hanzo-kai` implements the Kai controller loop, ledger, and tools.

## Review Process

1. Open a pull request against `main` stating what changed and why, linking the issue.
2. Ensure CI passes across Linux, macOS, and Windows.
3. A maintainer will review and merge once checks and design review pass.

## Community Values

- Follow the [Code of Conduct](https://github.com/hanzoai/.github/blob/main/CODE_OF_CONDUCT.md).
- Report security issues privately to [security@hanzo.ai](mailto:security@hanzo.ai).
