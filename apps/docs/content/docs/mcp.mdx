# MCP

One Model Context Protocol server, one tool surface. Add **`hanzo-mcp`** to Claude Code (or Cursor, Claude Desktop, or any MCP client) and every Hanzo capability shows up through a single connection — no per-tool wiring.

> Looking for the hosted MCP server instead? **[Cloud MCP](/docs/mcp-tools)** is a URL with nothing to install, and its every tool is enumerated in the [tool catalogue](/docs/mcp-tools/all-tools). This page is the server that runs beside your editor.

```bash title="Add the Hanzo MCP to Claude Code"
claude mcp add --scope user hanzo -- npx -y hanzo mcp
```

Nothing to install first. npx fetches the `hanzo` launcher, and `hanzo mcp` is the
native Rust MCP server over stdio, downloaded and SHA-256 verified the first time
it runs. Bare `hanzo mcp` is stdio; `hanzo mcp -t sse` serves HTTP. Codex takes the
same command: `codex mcp add hanzo -- npx -y hanzo mcp`. With `npm i -g hanzo`
installed, `hanzo mcp` (or `hanzo-mcp`) runs it directly.

That one command exposes the full **19-tool canonical HIP-0300 surface** — one orthogonal, action-routed tool per capability, mirrored 1-to-1 across **Rust (`hanzo-mcp`)**, **TypeScript (`@hanzo/mcp`)**, and **Python (`hanzo-mcp` on PyPI)** over **stdio** and **streamable-http**:

| Tool | Actions / Capability |
|------|----------------------|
| **`fs`** | Filesystem & native `tgrep` trigram search (`read`, `write`, `edit`, `apply_patch`, `list`, `tree`, `search_text`, `stat`, `mkdir`, `rm`, `mv`, `cp`) |
| **`exec`** | Process execution, classified shell policy, background jobs & ephemeral runners (`exec`, `ps`, `logs`, `kill`, `wait`, `npx`, `uvx`) |
| **`code`** | Tree-sitter AST symbols, LSP, refactoring, `jq`, & cross-repo Cloud RAG (`symbols`, `outline`, `definition`, `references`, `diagnostics`, `rename`, `refactor`, `lsp`, `jq`, `search`, `context`, `ask`, `index`) |
| **`git`** | Git version control & worktrees (`status`, `diff`, `log`, `commit`, `branch`, `checkout`, `blame`, `stash`, `worktree`) |
| **`fetch`** | HTTP client, live web search, web reader & multimodal vision (`get`, `request`, `search`, `read`, `vision`) |
| **`workspace`** | Project discovery, roots, config, mode & host system info (`detect`, `projects`, `config`, `system`, `mode`, `version`) |
| **`browser`** | Web browser & CDP automation over ZAP (`navigate`, `snapshot`, `click`, `type`, `screenshot`, `evaluate`, `cdp`) |
| **`computer`** | Native OS desktop screen, mouse, keyboard & GUI control (`screenshot`, `click`, `move`, `type`, `key`, `window`) |
| **`ui`** | `@hanzo/ui` & `@hanzo/gui` design system registry (`search`, `get`, `blocks`, `install`, `tokens`) |
| **`kai`** | **Single Kai decision & controller tool** (`decide`, `choice`, `score`, `noul`, `run`, `plan`, `list`, `triggers`, `compact`, `tool_select`, `next_action`, `command_guard`, `injection_screen`, `extract`, `log_triage`, `recover`, `agent_step`) |

| **`hanzo`** | Unified Hanzo Cloud platform router (`service` + `action`: `auth`, `iam`, `kms`/`vault`, `connectors`, `platform`, `compute`, `billing`, `s3`, `social`, and every fleet capability at `api.hanzo.ai/v1`) |

## Client setup

```json title="Claude Desktop / Cursor — mcp config"
{
  "mcpServers": {
    "hanzo": {
      "command": "npx",
      "args": ["-y", "hanzo", "mcp"]
    }
  }
}
```

Sign in once (`hanzo auth login`) and the `hanzo` cloud tool + your connectors authenticate automatically; the local tools (`fs`, `exec`, `git`, …) work with no account.

## The tool index

Every tool the platform can expose is indexed at `GET api.hanzo.ai/v1/tool` (authenticated). The unified server presents them through the compact action-routed surface above. A tool's `source` is one of six values, and the order below is also the [precedence order](/docs/extend#precedence--who-wins-a-name-collision) — the lowest wins a name collision:

| Source | What it is |
|--------|-----------|
| `connector` | Linked cloud integrations (GitHub, Slack, Google, Discord, X, …) |
| `function` | User-defined functions |
| `zap-service` | First-party cloud service routes |
| `agent` | Agent entry points |
| `skill` | Packaged skills — listing only, never called |
| `mcp` | Tools on your org's own registered MCP servers |

Adding a source of your own is [Extend](/docs/extend).

## MCP as a Service

Beyond the unified server, Hanzo can also **host** any MCP server for you — deploy from any npx, uvx, or custom package with instant scaling and zero infrastructure to manage.

```bash title="Launch an MCP server"
hanzo mcp launch npx @modelcontextprotocol/server-filesystem
```

## Key Capabilities

- **Any MCP server** — Filesystem, Git, SQL, KV, Slack, GitHub, Notion, and more
- **1-click Deploy** — Launch any MCP server with a single command
- **Auto Scaling** — Scale from 0 to thousands of instances automatically
- **$0 Idle Cost** — Pay only for what you use, no idle charges
- **Secure Sandboxing** — Isolated containers with fine-grained permissions
- **15+ Regions** — Edge deployment for lowest latency globally

## Launch Methods

### NPX Packages

```bash
hanzo mcp launch npx @modelcontextprotocol/server-filesystem
hanzo mcp launch npx @modelcontextprotocol/server-github
hanzo mcp launch npx @modelcontextprotocol/server-slack
```

### UVX / Python

```bash
hanzo mcp launch uvx mcp-server-sqlite
hanzo mcp launch uvx mcp-server-postgres
```

### Custom Servers

```bash
hanzo mcp launch git://github.com/you/mcp-server
hanzo mcp launch docker://your-org/mcp-custom:latest
```

## Configuration

Deploy multiple servers with a single config file:

```yaml title="mcp-config.yaml"
version: "1"
servers:
  filesystem:
    package: "@modelcontextprotocol/server-filesystem"
    runtime: npx
    args: ["/workspace"]

  database:
    package: "mcp-server-postgres"
    runtime: uvx
    env:
      DATABASE_URL: "${secrets.DATABASE_URL}"

  github:
    package: "@modelcontextprotocol/server-github"
    runtime: npx
    env:
      GITHUB_TOKEN: "${secrets.GITHUB_TOKEN}"

  custom:
    image: "your-org/mcp-custom:latest"
    runtime: docker
    replicas: 3
```

```bash
hanzo mcp deploy
```
