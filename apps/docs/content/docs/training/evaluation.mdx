**If you cannot measure a change on a frozen held-out set, you cannot tell an improvement from a regression.** Hanzo's `/v1/eval` plane provides tenant-isolated evaluation datasets, reusable judges, rubrics, and live GenAI telemetry in one contract.

## Evaluation surface map

| Endpoint | Role |
|---|---|
| `POST /v1/eval/datasets` / `GET /v1/eval/datasets/{name}` | Create or inspect a named evaluation dataset |
| `POST /v1/eval/datasets/{name}/items` | Add graded `(input, expected, metadata, status)` test items |
| `POST /v1/eval/evaluators` / `GET /v1/eval/evaluators` | Define reusable model or Kai judges keyed by name |
| `GET /v1/eval/rubrics` | List structured scoring rubrics |
| `GET /v1/eval/runs` / `GET /v1/eval/scores` | Query run outcomes and per-item score distributions |
| `GET /v1/eval/traces` | Inspect traced spans behind scored outputs |
| `GET /v1/eval/metrics` | Org AI overview board: totals, cost in cents, error rate, latency percentiles |

## Build a release gate in four calls

<Tabs items={['CLI', 'SDK', 'HTTP', 'MCP']}>
<Tab value="CLI">
```bash
# 1. Create a golden dataset
hanzo eval datasets create --data '{"name":"refund-policy-golden","description":"50 hard billing refund cases"}'

# 2. Add graded items
hanzo eval datasets items create refund-policy-golden --data '{
  "input": {"ticket": "Charged twice on invoice #9124", "plan": "pro"},
  "expected": {"route": "auto_refund"},
  "status": "active"
}'

# 3. Register a reusable evaluator
hanzo eval evaluators create --data '{
  "name": "refund-accuracy",
  "judge_model": "kai",
  "score_name": "route_correct",
  "criteria": "Output matches expected refund workflow with zero policy violations."
}'

# 4. Inspect org AI telemetry & latency percentiles
hanzo eval metrics
```
</Tab>

```ts
import { Configuration, EvalApi } from 'hanzoai';

const evalApi = new EvalApi(new Configuration({ accessToken: process.env.HANZO_API_KEY }));
await evalApi.postEvalDatasets({
  name: 'refund-policy-golden',
  description: '50 hard billing refund cases',
});
await evalApi.postEvalDatasetsByNameItems('refund-policy-golden', {
  input: { ticket: 'Charged twice on invoice #9124', plan: 'pro' },
  expected: { route: 'auto_refund' },
  status: 'active',
});
const metrics = await evalApi.getEvalMetrics('24h');
console.log(metrics.data);
```

## Five metrics every release gate should enforce

1. **Task accuracy / pass rate** against pinned golden datasets.
2. **Paired win/loss delta** (`rescue` vs `damage`) using `GET /v1/benchmark/compare` — never compare unaligned subsets.
3. **Calibration (ECE)** on decision probabilities so abstention thresholds remain valid.
4. **Latency p50 / p95** from `GET /v1/eval/metrics`.
5. **Unit economics** (cents per 1,000 requests, cache hit rate) from `GET /v1/eval/metrics` and `GET /v1/billing/usage`.
