**Fine-tune Zen when you need permanent domain synthesis, proprietary code conventions, or custom reasoning patterns baked into model weights.** All Zen training runs on your choice of Hanzo managed GPUs or your own registered BYO compute fleet, billed transparently by the device-second.

## 1. Discover trainable base models & methods

Query `GET /v1/train/models` to see every base model, supported adaptation method (`lora`, `qlora`, `full`), device-second rate in nano-USD, objective terms, and dataset schemas.

## 2. Upload content-addressed training data

Compute the SHA-256 of your JSONL dataset and register it with `POST /v1/train/artifacts`. Hanzo returns a presigned S3 upload URL encrypted under your org's key (or `stored: true` if identical bytes are already deduplicated).

```bash
SHA=$(shasum -a 256 train.jsonl | awk '{print $1}')
BYTES=$(wc -c < train.jsonl | tr -d ' ')

curl -X POST https://api.hanzo.ai/v1/train/artifacts \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"sha256\":\"${SHA}\",\"bytes\":${BYTES},\"kind\":\"dataset\",\"name\":\"support-sft-v1\"}"
```

## 3. Submit a training job

Submit the job via `POST /v1/train/jobs` (or use the managed preset wizard on `GET /v1/ai/finetune/presets` and `POST /v1/ai/finetune/jobs`). Always declare a validation split and regression budget so bad checkpoints never silently ship.

<Tabs items={['CLI', 'HTTP']}>
<Tab value="CLI">
```bash
hanzo train jobs create --data "{
  \"base_model\": \"zen6-flash\",
  \"adaptation\": \"lora\",
  \"dataset_sha256\": \"${SHA}\",
  \"hyperparameters\": {\"epochs\": 3, \"learning_rate\": 2e-4, \"lora_rank\": 16}
}"
```
</Tab>

## 4. Stream events, metrics & artifacts

Follow live status transitions and validation suites without tight polling using cursor-based long polling (`GET /v1/train/jobs/{id}/events?wait=30`) and structured metric series (`GET /v1/train/jobs/{id}/metrics`):

```bash
JOB_ID="trj_..."
hanzo train jobs get "$JOB_ID"
hanzo train jobs metrics "$JOB_ID"
hanzo train jobs artifacts get "$JOB_ID"
```

Need to abort early? `POST /v1/train/jobs/{id}/cancel` stops executors cleanly and meters only device-seconds actually consumed.

## 5. Gate and publish to serving

A succeeded job's artifact can be published under an org-private model name via `POST /v1/train/jobs/{id}/publish` (or deployed from the fine-tune studio via `POST /v1/ai/finetune/deploy`). Jobs that breach their regression budget are rejected at publish time unless explicitly forced with an audit trail.

```bash
curl -X POST "https://api.hanzo.ai/v1/train/jobs/${JOB_ID}/publish" \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "zen6-flash-support-v1"}'
```

Once published, call your fine-tuned model directly on `POST /v1/chat/completions` or route into it from a custom Enso preset.
