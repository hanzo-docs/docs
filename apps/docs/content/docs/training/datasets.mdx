**Every model regression traces back to untracked data.** Hanzo separates mutable collection from immutable training snapshots so every checkpoint maps to an exact SHA-256 data digest.

## Three dataset planes

| Endpoint family | Purpose | Mutability | Primary consumer |
|---|---|---|---|
| `/v1/dataset` | Named org datasets with materialization, lineage, and export | Versioned snapshots via `materialize` | Risk models, structured feature pipelines, reproducible exports |
| `/v1/eval/datasets` | Graded evaluation sets (`input`, `expected`, metadata, status) | Append/archive items; frozen at run time | Evaluation harnesses, LLM/Kai judges, release gates |
| `/v1/train/artifacts` | Content-addressed byte blobs keyed by SHA-256 | Strictly immutable (encrypted per-org S3) | `POST /v1/train/jobs` datasets and output checkpoints |

## Decontamination & split hygiene

Before uploading a dataset blob to `POST /v1/train/artifacts`:

1. **Hash deduplication**: Deduplicate exact and near-duplicate user states by normalized SHA-256 before splitting train/validation/test.
2. **Entity-level grouping**: Split by customer account, repository, or ticket thread — never put two turns of the same conversation in both train and holdout.
3. **Holdout quarantine**: Store held-out test rows in `/v1/eval/datasets/{name}/items` and never export that dataset into training inputs.
4. **PII & secret scrubbing**: Scan candidate corpora with `POST /v1/security/scans` before upload so credentials and secrets never enter weights.
