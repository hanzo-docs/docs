# Sessions

A session groups every [trace](/docs/traces) that shares a `sessionId` — a multi-turn chat, a support thread, or a long-running agent run. Sessions turn a stream of individual requests into one reviewable timeline. Served by [Hanzo O11y](/docs/o11y), tenant-scoped by org.

## Starting a session

There is no "create session" call — a session comes into existence the moment a trace carries a `sessionId`. Set it as an OpenTelemetry attribute (or the trace field) and reuse the same value across turns.

```python
with tracer.start_as_current_span("chat.turn") as span:
    span.set_attribute("session.id", "sess_9f")   # groups this trace into the session
    span.set_attribute("user.id", "u_42")
    respond(message)
```

## Read them

```bash
curl "https://api.hanzo.ai/v1/o11y/llm/sessions?limit=50" \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

Sessions are an aggregation over the same spans your traces are built from, which
is why there is nothing to keep in sync. Filter with `start` and `end` (unix
**milliseconds**; omit both for the last 24 hours), `sessionId`, `userId`,
`model`, `name`, `traceId`, `offset`, and `limit`.
