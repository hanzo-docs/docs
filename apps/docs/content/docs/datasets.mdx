# Datasets

A dataset is a curated collection of **items** — each an input paired with an expected output — used to evaluate models and agents. Datasets are the fixed yardstick an [experiment](/docs/experiments) measures against. Part of the Hanzo Cloud evaluation surface, tenant-scoped by org.

## Create a dataset

```bash
curl -X POST https://api.hanzo.ai/v1/evals/datasets \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-qa",
    "description": "Golden answers for common support questions"
  }'
```

The `name` is the key — POSTing it again edits the dataset and leaves its items
untouched.

## Add items

Each item carries an `input` and an `expectedOutput` — raw JSON, up to 64 KiB
each — plus free-form `metadata` that travels with the item into every run.

```bash
curl -X POST https://api.hanzo.ai/v1/evals/datasets/support-qa/items \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "input": { "question": "How do I rotate an API key?" },
    "expectedOutput": "Points at the console key page and warns about in-flight requests.",
    "status": "ACTIVE"
  }'
```

`status` is `ACTIVE` (the default) or `ARCHIVED`. A run evaluates active items
only, so archiving retires an item without breaking the runs that already
reference it. Supply your own `id` to make the write idempotent — the same id in
the same dataset replaces in place.

List them with `GET /v1/evals/datasets/support-qa/items`, which includes archived
items; `GET /v1/evals/datasets/support-qa` returns the dataset with a live item
count.

## Run against a model

A dataset becomes useful when you run it. Pass the dataset name to an [experiment](/docs/experiments) — `POST /v1/evals/runs` — to score every item against a model, optionally with an LLM judge.
