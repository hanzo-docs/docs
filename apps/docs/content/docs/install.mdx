# Install

## The CLI

One line puts the `hanzo` CLI, the MCP server and the `dev` agent on your PATH,
as prebuilt native binaries verified against their published checksums:

```bash
curl -fsSL hanzo.sh | sh
```

They land in `~/.local/bin`. Nothing is compiled and no runtime is needed first.
To take a single tool, ask for it by name — `hanzo.sh/cli` or `hanzo.sh/mcp` —
or on macOS install the CLI from the tap:

```bash
brew install hanzoai/tap/hanzo
```

Then sign in with `hanzo auth login`. Every command is in the
[CLI reference](/docs/services/platform/getting-started/cli).

## One key, one address

Whatever you install, it points at the same place: `api.hanzo.ai`, authenticated
with one key. That is why a project can start on a snippet and end up calling the
API from a server without changing accounts, keys, or hosts — the surface widens,
the credential does not.

Mint a key in the [console](https://console.hanzo.ai), or see
[Getting Started](/docs/getting-started) for the five-minute path from nothing to
a first call.

## Nothing to install

Every endpoint an SDK reaches is reachable directly. A stack with no Hanzo
package — or one you would rather not add a dependency to — uses the
[HTTP API](/docs/api) and loses nothing but the typing.

## Connecting, not installing

Installing puts Hanzo *into* your app. Connecting points Hanzo *at* a service you
already run — GitHub, Slack, Google, or any MCP server. That is a different
catalog: see [MCP and connectors](/docs/mcp).
