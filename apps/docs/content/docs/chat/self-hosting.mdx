# Self-Hosting Hanzo Chat

There are two ways to self-host a browser chat interface in the Hanzo open-source stack, depending on whether you want a single offline binary or a multi-user workspace:

1. **Single-binary offline chat (`hanzoai/engine`)** — Zero Node.js, zero database, zero OIDC setup. `hanzo-engine` serves open-weight models and an embedded web UI at `/ui` from one Rust binary.
2. **Full web workspace (`hanzoai/chat` / `@hanzo/chat`)** — The Vite + React single-page application that powers [hanzo.chat](https://hanzo.chat), connected to either `https://api.hanzo.ai` or your own self-hosted [`hanzoai/cloud`](https://github.com/hanzoai/cloud) + [`hanzoai/iam`](https://github.com/hanzoai/iam) stack.

For the full multi-repo architecture and air-gapped staging steps, see **[Self-Hosting & Air-Gapped](/docs/self-hosting)**.

---

## Option 1: Single-binary local & offline chat (`hanzoai/engine`)

If your goal is to run open-weight models locally or on an air-gapped machine and chat with them in a browser immediately:

```bash
# Install hanzo-engine (auto-detects Metal on macOS, CUDA or CPU on Linux; requires Rust 1.88+)
curl --proto '=https' --tlsv1.2 -sSf https://raw.githubusercontent.com/hanzoai/engine/main/install.sh | sh

# Start a model with the built-in web UI
hanzo-engine serve --host 127.0.0.1 -p 1234 -m zenlm/zen-nano-0.6b --no-advertise
```

Open `http://127.0.0.1:1234/ui` in your browser, or test the OpenAI-compatible endpoint directly:

```bash
curl -sS http://127.0.0.1:1234/v1/models
```

On an air-gapped machine, pass a local weights directory (`-m ./weights/zen-nano-0.6b`) with `HF_HUB_OFFLINE=1`; see [Self-Hosting & Air-Gapped](/docs/self-hosting#3-running-completely-air-gapped-zero-outbound-network).

## Option 2: Full web workspace (`hanzoai/chat`)

[`hanzoai/chat`](https://github.com/hanzoai/chat) (`@hanzo/chat`) is a pure client-side Vite + React application built on `@hanzo/ui`, `@hanzo/ai`, and `@hanzo/iam`. It requires **no MongoDB, Meilisearch, or Node.js backend** of its own — all state, conversations (`/v1/agents/chat/conversations`), models (`/v1/models`), and completions (`/v1/chat/completions`) live behind the `/v1` API origin you point it at.

### Local development & verification

Requires Node.js `22`+ and `pnpm`:

```bash
git clone https://github.com/hanzoai/chat
cd chat
CI=true pnpm install --no-frozen-lockfile

# Run the test suite and typechecker
pnpm typecheck
pnpm test

# Start the local dev server on http://localhost:3090
pnpm dev
```

By default, `pnpm dev` proxies `/v1` requests to `https://api.hanzo.ai`. To point the client at a local [`hanzoai/cloud`](https://github.com/hanzoai/cloud) and [`hanzoai/iam`](https://github.com/hanzoai/iam) stack instead:

```bash
VITE_HANZO_API=http://127.0.0.1:8080 \
VITE_HANZO_IAM=http://127.0.0.1:8000 \
pnpm dev
```

| Environment variable | Purpose | Default |
|---|---|---|
| `VITE_HANZO_API` | Base origin for `/v1/*` API requests (`models`, `chat/completions`, `agents/chat/conversations`) | Same-origin `/v1` proxy in dev; `https://api.hanzo.ai` in production builds |
| `VITE_HANZO_IAM` | Base origin for OpenID Connect discovery and PKCE login (`@hanzo/iam`) | Brand issuer (`https://iam.hanzo.ai`) |

### Static production build

Build a static bundle into `dist/` (includes `404.html` SPA fallback so client-side routes like `/auth/callback` resolve on any static object store or reverse proxy):

```bash
VITE_HANZO_API=https://api.yourdomain.com \
VITE_HANZO_IAM=https://id.yourdomain.com \
pnpm build
```

Serve `dist/` from [`ghcr.io/hanzoai/spa`](https://github.com/hanzoai/chat), `hanzoai/ingress`, Caddy, or Nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name chat.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/chat.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chat.yourdomain.com/privkey.pem;

    root /var/www/hanzo-chat/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### Production checklist

- [ ] Point `VITE_HANZO_API` and `VITE_HANZO_IAM` at your HTTPS `/v1` API and OIDC issuer before running `pnpm build`
- [ ] Register `https://chat.yourdomain.com/auth/callback` in your Hanzo IAM application's `redirectUris`
- [ ] Enable CORS on your `/v1` gateway for `https://chat.yourdomain.com` (or proxy `/v1` on the same origin)
- [ ] Verify `/auth/callback` serves `index.html` (handled automatically by `try_files` or the emitted `404.html`)
